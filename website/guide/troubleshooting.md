# 运行要求与排错

这份文档按「现象 → 原因 → 怎么做」列常见问题。先看[运行要求](#运行要求)，再看[出问题先看哪三处](#出问题先看哪三处)——多数毛病在那三处就能定位。

## 运行要求

| 项目 | 要求 |
| ---- | ---- |
| 系统 | Windows 10 及以上（x64 安装包）；macOS 12 及以上（只提供 Apple Silicon 版）；主流 64 位 Linux 发行版（AppImage / deb） |
| 内存 | 推流时建议 8 GB 以上（FFmpeg 常驻内存）；只写稿、合成、导出这类不推流的用法，普通办公机够用 |
| 磁盘 | 应用本体含随包分发的 FFmpeg，装完占几百 MB；建议再留 2 GB 以上给音频缓存与导出产物 |
| 网络 | 能出网访问你在用的语言模型与语音合成服务商域名。直推推流额外要能连上 RTMP 服务器 |
| 账号 | 语言模型与语音合成的密钥由你在服务商处自备。软件不代付、不带额度 |
| 平台连接器 | 要接真实评论，另装平台连接器（抖音「直播数据助手」）并保持运行。主程序不含任何平台 SDK |

应用本身不监听端口、不提供服务端：所有数据存本机，额度消耗发生在你自己的服务商账号里。数据目录、备份与磁盘占用见下文[数据、磁盘与备份](#数据、磁盘与备份)。

## 出问题先看哪三处

**一、底部状态栏。** 左侧是播出状态与页面（`就绪 / 播报中 / 已暂停 · 当前页面`）加一段音波。右侧几格报的是「这一路现在通不通」：

| 格子 | 可能出现的文案 | 说明 |
| ---- | -------------- | ---- |
| 导演大脑 | `导演 小云（DeepSeek）` | 这一场谁在指挥 |
| 导演大脑 | `导演大脑未配置 → 去配置`（红色，可点） | 点一下直达设置 → 导演 |
| 卡司嗓音 | `卡司嗓音 小云 · 火山` | 节目卡司第一张的嗓音、实际走哪家 |
| 出镜 | `出镜 店主的嗓音失效 → 去修复`（红色，可点） | 点一下直达设置 → 语音合成 |
| 合成中 N | 只在后台合成时出现 | 有 N 条正在合成 |
| 推流 | `未出声` / `未推流` / `推流未配置` / `推流中 N kbps` / `重连中(N)` / `推流出错` | 伴侣模式看「出声」，直推看「推流」 |
| 连接器 | `连接器未接入` / `连接器连接中…` / `连接器已连接` | 评论通道 |

**二、开播确认清单。** 在直播台点「启动节目」，先弹「开播确认 · 节目名」，逐条列检查项：绿色打勾是通过，黄色三角是警告，红色叉是阻断。阻断项不处理开不了播；有问题的行右侧带「去修复 →」，分别是去配大脑 / 去选音色 / 去检查合成 / 去测发音 / 去写编排 / 去连接 / 去推流设置，点了直达对应页面或设置栏目。底部按钮是 先去处理 / 提前合成全部（滚动节目）/ 去生成底稿（还没写稿时）/ 重新预检 / 确认开播。注意黄色警告不会拦你——模型没配、评论没接这类情况照常出声，但要清楚自己接受的是什么。

**三、提示条与日志文件。** 右下角弹出的提示会把技术原文折进「技术细节」，先照人话部分处理。窗口闪退、启动一半没反应这类「无声退出」，看用户数据目录里的 `crash.log`：它按行追加时间、事件类型（`uncaughtException` / `render-process-gone` / `exit`）与堆栈，不含业务数据。

## 启动与安装

安装与平台差异的完整说明在[下载与安装](/download)，这里只列失败情况。

| 现象 | 原因 | 怎么做 |
| ---- | ---- | ------ |
| Windows 弹「Windows 已保护你的电脑」「未知发布者」 | 安装包没有代码签名 | 点「更多信息」→「仍要运行」。这是未签名应用的正常提示，不是文件坏了 |
| macOS 说「应用已损坏」或打不开 | 未签名 + 下载隔离属性 | 终端执行 `xattr -cr /Applications/小云播客坊.app` 后重新打开 |
| Intel Mac 上装不上或起不来 | 只构建了 macOS arm64 包，没有 Intel 版 | 换 Apple Silicon 机器，或按仓库 README 的命令自行构建 |
| macOS / Linux 上窗口细节、音频设备路由不对劲 | 这两个平台尚未真机验证 | 到 [Issue](https://github.com/xy200303/yuncast/issues) 说明系统与现象 |
| 双击图标没反应，或开了一会儿自己退了 | 启动期异常 | 看用户数据目录里的 `crash.log` 最后几行，连同系统版本一起提 Issue |
| 再点一次图标没开第二个窗口 | 单实例锁 | 它会把已经打开的窗口提到前台，数据只有一份 |
| 窗口一片白 | Windows 标题栏覆盖层偶发首帧没画出来 | 程序检测到空画面会自动重新加载（最多两次）；依然白屏就提 Issue，附 `crash.log` |
| 设置 → 关于里「检查更新」报错 | 更新走 GitHub Releases，网络到不了 GitHub；开发环境本来不走更新通道 | 到 Releases 手动下载新包覆盖安装，数据不受影响 |

## 模型与密钥

语言模型的报错在「设置 → 语言模型」，语音合成的在「设置 → 语音合成」，别把两边的密钥搞混。

| 现象 | 原因 | 怎么做 |
| ---- | ---- | ------ |
| `401` / `403`、`invalid api key` | 密钥错、密钥被服务商停用、账号欠费，或这个模型没开通 | 到对应接入里核对密钥与余额；接入卡上的「测试」会把地址、密钥、模型名一整套验一遍 |
| `404`、`model not found` | 模型名不对。要填服务商文档里那个模型 ID，不是界面上看到的名字 | 编辑接入 → 模型，从目录里挑一个，或把控制台文档里的 ID 粘进去 |
| `fetch failed` / `ECONNREFUSED` / `ENOTFOUND` / 超时 | 网络不通、域名解析不了，或本地模型服务没起来 | 换网络或查代理；跑本地模型时确认服务已启动、地址端口对得上（用「自定义接口」手填地址） |
| 状态栏红字「导演大脑未配置」 | 只在「语言模型」里加了接入，没在「导演」里指定用哪条、哪个模型 | 设置 → 导演：给全局大脑起名，挑一条接入和一个模型 |
| 主播不写稿、不互动，但声音照播 | 引擎与模型解耦：模型不可用只影响生成新内容 | 按上面的办法修模型。已经合成好的音频不受影响，照常播 |

补充两点：程序启动时把 DNS 结果顺序设成 IPv4 优先，专治 IPv6 默认线路黑掉导致的长时间卡住；接入卡上的「测试连通」用表单里当前填的值直接测，不必先保存。

## 语音合成与音色克隆

| 现象 | 原因 | 怎么做 |
| ---- | ---- | ------ |
| 状态栏「出镜 XX 的嗓音失效」 | 克隆音色只认克隆时那条接入和那个模型，接入删了、模型没启用就失效，没有回退；系统音色则需要有一条启用了它所属模型的可用接入 | 把接入加回来，或用现有接入重新克隆一个；系统音色到接入里勾上对应模型（豆包 maas 系模型还缺「业务空间 ID」时也要补上） |
| 克隆提交后失败 | 样本质量或账号权限 | 换一段更清晰、无伴奏、语种一致的人声。火山的 45001104 是声纹校验没过，45001109 是样本文本校验没过，45001122 是没检测到有效人声 |
| 百炼提示需要公网可访问的音频地址 | 百炼复刻接口只收 URL，不收本地文件 | 点「上传样本并取地址」，程序把样本临时传到第三方文件站换回直链；样本是隐私内容，只在点按钮时上传，不想上传就自己粘一个地址 |
| 「上传样本并取地址」失败 | 那个第三方文件站连不上 | 换个网络重试，或自己把样本传到能公网访问的地方再粘地址 |
| 「这条接入里没有可复刻的模型」 | 接入里没勾复刻类模型 | 编辑接入，勾上复刻模型（火山 `seed-icl-1.0`/`2.0`，百炼 cosyvoice 各版与 qwen-audio） |
| 播客专用模型不能用单句测试 | 它整期合成，不吃单句文本 | 到预制节目的「生成节目音频」整期合成 |

样本的硬要求：10–30 秒清晰人声、无背景音乐；提交时勾选「我确认已获得录音人的明确授权」，提交时间会留痕。火山账号需先开通「声音复刻」，样本支持 wav / mp3 / ogg / m4a / aac / pcm，录音产物（webm）由程序自动转成 mp3；火山复刻走付费音色，首次正式合成即转正收费，试听 7 天没正式调用会被删除。百炼复刻创建即完成、没有异步训练，音色长期有效，但创建时绑定的目标模型之后不能改。

判断是不是合成这一侧的问题：到音色库点「试听」，或在接入卡上点「测试」。

## 没有声音

按顺序排查，一步能排掉一大半：

1. **先看有没有在播。** 状态栏左侧是「播报中」还是「已暂停」。暂停时按播放条的暂停继续。
2. **看播放条音量。** 音量拉到 0 相当于紧急静音：AI 两路（本机监听与推流那一路）一起哑，麦克风人声不受影响。点音量图标恢复，会回到上次的音量。
3. **看主播有没有音色。** 主播团的人设卡必须选音色，没选时新内容合不出来（存量音频照播）；开播确认里会给一条「还没给主播选音色」的警告。
4. **看系统输出设备。** 应用不做输出设备选择，声音走系统默认播放设备。确认默认设备是你的耳机或音箱，也没被别的软件独占（Windows 在「设置 → 系统 → 声音」里看）。
5. **伴侣模式下观众听不到。** 应用只负责出声，采集在你的直播软件那一侧：在直播软件里加「系统声音」或「扬声器」来源。只加了麦克风，就会出现「你听得到、直播间听不到」。
6. **直推模式下观众听不到。** 推的是应用内部混好的三路 PCM（AI 语音、BGM、麦克风），和系统音量无关，但和播放条音量有关：拉到 0，推流那一路也哑。
7. **真人接管要麦克风权限。** 第一次用会弹系统授权；被拒之后系统不再弹，要到系统设置里手动开（macOS：系统设置 → 隐私与安全性 → 麦克风；Windows：设置 → 隐私和安全性 → 麦克风，允许桌面应用访问）。
8. **测一下这条嗓子本身行不行。** 音色库的「试听」，或设置 → 语音合成里接入卡的「测试」——它合成一句并直接出声；如果返回「音频没能放出来」，说明系统没有可用输出设备或播放被系统拒绝，回到第 4 条。

接入卡上的「测试」会记下发音测试时间，开播确认用它判断凭据是否可能失效（超过 24 小时给黄色提醒）。编辑表单里的「测试连通」也能出声，但不算那条记录。

## 推流

状态栏的推流格只说这一路通道的状态，两格口径不同：整机播没播看左边那格，这里看输出。

| 文案 | 情况 |
| ---- | ---- |
| `未出声` | 伴侣模式、还没开播。正常 |
| `未推流` | 直推模式、还没点「开始推流」 |
| `推流未配置` | 直推模式，服务器地址或推流密钥还是空的 |
| `推流中 N kbps` | 直推正在推，N 是当前码率 |
| `重连中(N)` | 断流后自动重推，这是第 N 次 |
| `推流出错` | 连续重推失败，提示里带原因 |

**直推要填两项。** 设置 → 推流 → 模式选「直推 RTMP」，填「服务器地址」（`rtmp://…`）和「推流密钥」，两段都在平台开播页的推流信息里，别把整串粘进同一个框。填完保存，再点「开始推流」。

**FFmpeg 不用自己装。** 它随安装包分发（`ffmpeg-static`，打包时解包到程序资源目录），静态帧是 720p15，视频开销很小。若提示 ffmpeg 二进制不可用，重装应用即可。

**断流会自己重推。** 间隔从 2 秒起翻倍，最多 5 次；仍失败就报「推流断了：到 设置 → 推流 检查推流地址和密钥，再确认网络正常」。次数在状态栏显示为「重连中(N)」。

**伴侣模式不需要任何配置。** 但它真的不出声要看上一节第 5 条：你的直播软件得把本机声音采进去。

## 评论收不到

前提：主程序不内置平台 SDK，也没有内置评论模拟器。评论、礼物、进场都来自单独的平台连接器（抖音「直播数据助手」），它得装着、开着，并且和本应用对上暗号。

**对上暗号的三步。** 打开连接器的「设置 → 智能体接口」，把它显示的端口与令牌抄进本应用的「设置 → 连接器」，点「保存并重连」。端口默认 8102，范围 1–65535；协议是本机 MCP（`http://127.0.0.1:<端口>/mcp`，带 Bearer 令牌）。

**判断连没连上。** 设置 → 连接器的徽章会写 `已连接 · 收 N 条`，状态栏那格写「连接器已连接」。连不上时它按 1 秒起、最长 30 秒的退避自动重试，所以先把连接器打开，再回来看这格；也可以点「立即重连」催一次。

| 现象 | 原因 | 怎么做 |
| ---- | ---- | ------ |
| 状态栏一直「连接器未接入」 | 连接器没运行，或端口/令牌抄错 | 确认连接器在跑；核对端口与令牌是否完全一致，改完点「保存并重连」 |
| 徽章是「连接失败（自动重试中）」 | 端口上没人应答，或令牌不对 | 同上；连接器端口被占用时，两边换成同一个空闲端口 |
| 已连接，但一条评论都没有 | 连接器那边没进直播间 | 用连接器的演示模式先跑通链路——本应用评论流空着时也提示「开连接器的演示模式试试」 |
| 评论在流里滚，主播不理 | 节目的互动总闸或白名单没开 | 节目的事件规则里「让主播看到直播间动态」是总闸；播出中也能改：播放条「⋯」→「自动响应（N）」 |
| 主播回复总是慢半拍 | 收件箱是攒批的，不是逐条即时 | 同一作者同一内容 30 秒内只记一次；普通事件每批最少攒 5 秒、最多等 30 秒；每分钟最多唤醒主播 6 次；过了 5 分钟还没处理的事件作废。单批最多带 20 条、1500 字，超出的折进摘要 |

本机回环流量一般不需要动防火墙；如果装了会拦截回环连接的安全软件，给它放行。

## 数据、磁盘与备份

| 平台 | 用户数据目录 |
| ---- | ------------ |
| Windows | `%APPDATA%\YunCast` |
| macOS | `~/Library/Application Support/YunCast` |
| Linux | `~/.config/YunCast` |

目录里放什么：

- `yuncast.db`：全部业务数据与应用配置，SQLite、WAL 模式（旧版叫 `agentanchor.db`，升级后首次启动自动改名）
- `secret.key`：凭据加密钥匙，数据库里的密钥字段用 AES-256-GCM 加密后存
- `blobs/`：音频、音色样本、素材附件，按内容寻址存储
- `blobs-tmp/`：临时文件，到期自动清
- `crash.log`：崩溃现场，闪退排查用
- 从旧版本升上来的机器上可能还有 `config.json.migrated`、`voices/`、`audio-cache/`，是历史结构遗留

::: warning 备份要连 secret.key 一起拷
只拷数据库不够：`secret.key` 不在，里面加密的密钥就解不开，所有凭据都得重填。
:::

**备份就是整目录拷贝。** 退出应用后把整个目录复制走，恢复时放回原位。恢复到别的用户目录（换了 Windows 用户名、换了机器）时，库里记的旧绝对路径会对不上，旧音频可能读不出来，路径一致最稳。要用别的目录，可以在启动前设环境变量 `YUN_CAST_USER_DATA` 指过去。

**卸载与更新不动数据。** 卸载程序显式关掉了删数据，覆盖安装与自动更新也不碰用户目录；要彻底清空得手动删目录。

**磁盘占用。** 合成音频与导出产物是主要增量。导出前程序会按待导出总量估算所需空间（合并导出按约 2.5 倍预留），不够就直接拒绝并告诉你可用多少。音频缓存有容量上限（默认 500 MB），超出按最久未见逐出；音色样本与素材附件属于长期资产，不会被自动清理。

## 怎么反馈

到 [GitHub Issues](https://github.com/xy200303/yuncast/issues) 提，附上这些能让问题一次定位：

- 版本号：设置 → 关于里写着，那里也有 GitHub 与官网入口
- 系统与版本（Windows 10/11、macOS、Linux 发行版），以及安装包类型
- 复现步骤：点了哪里、之前做过什么、期望看到什么、实际看到什么
- 截图或录屏；报错弹窗里的「技术细节」原文
- 闪退、启动一半退出这类问题，附上用户数据目录里的 `crash.log`

提交前把截图和日志里的 API Key、连接器令牌遮掉。
