# 01 · 总体设计：Agent Anchor（智能体主播）

> 状态：已整合定稿 · 2026-10-10
> 本文档由旧仓库（sonic-anchor）docs 07–10 四篇方案整合而成，矛盾处以本文为准。
> 有效前序文档：02-TTS选型调研、03-合规清单。旧仓库的 01/03/04/05 描述的是上一代 Vue 工具版，已归档不再适用。

## 1. 产品定位

**从「话术播放器」升级为「基于智能体的主播」。**

上一代的问题：LLM 一次性生成话术 → 预合成 → 轮播；评论回复是单次问答。无上下文、无记忆、无人设、商品资料只有一个提示词字段。

本代目标：AI 像真人主播一样工作——

- **有人设**：性格、口癖、背景、禁区，贯穿所有输出
- **有知识**：多模态商品资料库（文本/图片/文档/价格表/剧本）
- **有记忆**：场内上下文连贯，跨场认识老粉
- **有感知**：对直播间现场（进场/礼物/冷场/库存）实时反应
- **有腹稿**：接下来要讲的内容提前备好，且随时根据现场修订

## 2. 形态与技术栈

**纯桌面端应用，无服务端。** 唯一的网络依赖是 LLM/TTS 云 API。

| 层 | 选型 |
|---|---|
| 桌面壳 | Electron 44（内置 Node ≥22.19，pi-agent 硬性要求） |
| 构建 | electron-vite 5 |
| 视图 | React 19 + Tailwind CSS 4 + shadcn(radix-ui) + zustand + lucide-react |
| 智能体 | `@earendil-works/pi-coding-agent` SDK（含 pi-ai / pi-agent-core；MIT 协议） |
| 数据 | `node:sqlite`（Electron 自带，免原生重编译）+ safeStorage 加密凭据 |
| 音频/推流 | 搬迁旧版：WebAudio 三总线引擎、FFmpeg 混音推流 |
| TTS | 火山引擎 + 阿里云百炼双通道（见 02） |
| 评论接入 | 抖音直播伴侣 PipeSDK 原生模块本地直连（不经过任何服务端） |

pi-agent 集成要点：SDK 路线（白拿自动上下文压缩 + JSONL 会话树持久化）；`tools: []` 关掉全部编码/shell 工具，只挂自定义工具；`systemPromptOverride` 承载人设；资源目录全部重定向到应用数据目录。

## 3. 核心架构：单脑 + 话术池 + 事件触发

```
事件源（PipeSDK / 定时器 / 池状态 / 人工）
   │
   ▼
EventBus ──▶ TriggerRuntime（过滤·聚合·节流·冷却·预算）
   │                │
   │                ├── tool 模式：确定性模板直连话术池（不过 LLM）
   │                │
   ▼                └── steer/task 模式 ──┐
感知层 Agent（flash 级小模型，不说话）     │
 评论分析员 / 情报员(库存价格) /            │
 记忆管理员 / 氛围观察员                    │
   │ 结构化情报（不是话术）                 │
   ▼                                       ▼
┌─────────────────────────────────────────────┐
│ 主播 Agent（唯一话术生产者，pro 级主力模型）    │
│ 人设 + 剧本 + 情报 + 记忆 + 池状态             │
└──────────────────┬──────────────────────────┘
                   │ 池操作工具
                   ▼
            话术池 SpeechPool（唯一播放出口）
            排序 · 预合成窗口 · 去重 · 限流 · 时效
                   │
                   ▼
        TTS（按条目音色路由）→ 音频引擎 → FFmpeg 推流
```

三条铁律：**一切声音走话术池；一切外发动作走 CompanionBridge（预留）；一切 LLM 决策收敛到主播 Agent。**

另有两条架构约束：**一台机器同一时间只支持一场直播**（单 Agent + 单池）；**平台相关配置（推流/连接器/平台）随场次走**，全局设置只作默认值。

### 3.1 单脑架构（为什么是单脑）

主播 Agent 不实时说话，只是内容生产者——话术池解耦了生产和播放，它有充足时间消化全部情报再开口。多脑仲裁解决的是"多个生产者抢出口"的冲突，只有一个生产者时冲突不存在，而且：

- 连贯性免费（所有信息在同一上下文）
- 成本几分之一（主力模型只有一个，辅助 Agent 全是 flash 级）
- 决策链路一环（情报进上下文 → 直接产出），无裁决层延迟和误判

**群播多音色 = 编剧模式**：主播 Agent 一个脑子写多个角色的台词，条目带 `voiceId` 路由到不同音色。观众听到多角色对话，背后是同一个编剧，配合天衣无缝。将来若需真正的多独立人格（双主播辩论式带货），再演进多脑模型，池和工具层不用改。

### 3.2 话术池（SpeechPool）

任何声音进直播间的唯一入口。条目模型：

```ts
interface SpeechItem {
  id: string
  sessionId: string
  text: string
  turnId: string              // 话轮：同一批连续条目原子播出，不被插队拆开
  seq: number
  voiceId: string             // 角色音色（编剧模式）
  source: { agentId: string; kind: 'scene' | 'reply' | 'interact' | 'announce' | 'filler' | 'manual' | 'reaction' }
  lane: 'interrupt'           // 硬打断（场控/人工特权）
      | 'next'                // 当前播完即播（评论回复）
      | 'normal'              // 常规队列
      | 'filler'              // 冷场垫底
  dedupeKey?: string          // 未播条目去重
  expiresAt?: number          // 时效过期不播
  replyTo?: { commentId: string; author: string }
  status: 'pending' | 'synthesizing' | 'ready' | 'playing'
        | 'done' | 'interrupted' | 'skipped' | 'failed' | 'expired'
  createdAt: number
  playedAt?: number
}
```

**预合成窗口**：队列前 5 条提前送 TTS，播放只取 `ready` 条目，零合成延迟；排序变化时窗口重算。LLM 慢/崩都不卡直播。

**插队语义（回复评论）**：剧情话术播放中 → 回复条目进 next 道 → 当前播完 → 播回复 → 主播 Agent 感知到"刚插播了回复"，生成衔接句续讲剧情。

**硬打断恢复**：被打断条目标 `interrupted` 并通知主播 Agent，由它决定重述/续讲/放弃（不从音频中间接）。

**兜底链**：池有 ready → 等 pending 合成 → filler 暖场话术轮播 → 纯 BGM + steer 主播「冷场了，带节奏」。

### 3.3 主播 Agent 的池操作工具

| 工具 | 语义 |
|---|---|
| `say(text, voice?)` | normal 车道 |
| `insert_next(text, voice?)` | next 车道（评论回复） |
| `revise(itemId, newText)` | **修订未播条目**：作废旧音频重合成 |
| `revoke(itemId)` / `reorder(itemIds)` / `clear_lane(lane)` | 池管理 |
| `get_pool_status()` / `get_recent_played(n)` | 自查防重复防矛盾 |
| `advance_scene(sceneId)` | 推进剧本 |
| `search_knowledge(query)` / `check_price(productId)` | 知识库/价格护栏 |
| `lookup_viewer(name)` / `remember_viewer(...)` | 长期记忆读写 |

约束：`playing`/`done` 不可改（说出去的话泼出去的水）；价格只能出自 `check_price`（护栏）。

**杀手锏——腹稿实时修订**：池里未播内容随时可改。库存报警 → 情报员通知 → 主播 `revise` 掉「库存还有 500 件」改成「只剩 30 多件了」。观众听到的永远是最新口径。

### 3.4 话轮与捧场例外

一个话轮 = 1~3 条连续条目（`turnId` 绑定），池排序时原子不可拆——插进来的永远是完整话轮，不是半句话。捧场短句（「对！」「没错～」）走豁免通道：`kind='reaction'`、≤20 字、每角色每分钟 ≤2 条、只在话轮间隙播出。调味料有额度就不喧宾夺主。

### 3.5 事件触发体系

```ts
interface LiveEvent {
  id: string
  type: string                // domain.action：viewer.join / gift.received / pool.empty / timer.interval / …
  source: 'pipe' | 'pool' | 'timer' | 'agent' | 'human' | 'system'
  payload: Record<string, unknown>
  ts: number
}
```

触发器（声明式规则，存库可配置）：`on(event, filter) → target(mode, promptTemplate/toolAction) + throttle`。

**三种模式**：`tool`（不过 LLM，模板直连，送礼感谢/点赞里程碑）、`steer`（插一句引导）、`task`（给主播 Agent 派任务）。不是每件事都值得过 LLM。

**风暴防护五道**：条件过滤 → 聚合窗口（进场 5 秒攒一批：「欢迎 xx 等 8 位朋友」）→ 冷却 → 单场预算 → 全局 LLM 速率帽。

**内建触发器**：开场白 / 欢迎新人 / 老粉回归 / 送礼感谢 / 点赞里程碑 / 冷场自救 / 整点带节奏 / 下播道别。

**扩展预留**：EventRegistry + ToolRegistry 两张注册表。未来「自动上架/发福袋」= 注册新事件 + 新工具 + 新触发器模板，出站统一走 CompanionBridge 抽象（鉴权/审计/合规集中处理，现在只留接口，接入前对照 03-合规清单复核）。

### 3.6 记忆系统

| 层 | 内容 | 实现 |
|---|---|---|
| 场内 | 这场谁问了什么、我说过什么 | pi 会话上下文 + 自动压缩（长场次刚需）+ 已播话术回流 |
| 本场 | 下播总结（亮点/翻车/高频问题） | 主播 Agent 自我复盘写入 `episode_summaries` |
| 长期 | 老粉画像、历史偏好 | SQLite `viewer_profiles` / `agent_notes`，`lookup_viewer` 工具 + `transformContext` 按预算（≤800 tokens）注入 |

断播续播：会话树 JSONL 落盘，从原会话继续。

## 4. 知识库（多模态资料包）

| 类型 | 处理 |
|---|---|
| 文本/FAQ | 直接编辑，关键词索引 |
| Word/PDF | mammoth / pdf-parse 解析入库（搬旧代码） |
| 图片（产品图/证书/质检报告） | 多模态模型先出图文描述入库；检索命中时带描述（模型支持 vision 时带图） |
| 表格（价格表/规格表） | 结构化解析，`check_price` 直接查 |
| 剧本/剧情线 | 场景序列（开场→痛点→讲解→互动→催单→收尾），每场景有目标/要点/禁忌，`advance_scene` 推进，提词器显示当前场景 |

检索第一版：关键词 + 结构化查询（零依赖可解释）；向量检索留作增强（豆包/百炼 embedding API）。

## 5. UI / 布局（TermPilot 风格）

专业工具风：13px 小字密度、亮/暗/跟随系统双主题、无边框窗口。

```
┌──────────────────────────────────────────────────────────┐
│ DragStrip (h-10 可拖)                  [场次] [_][□][×]   │
├──────────┬───────────────────────────────────────────────┤
│          │ TabBar (h-10)：直播台│主播团│知识库│场次│数据  │
│ 侧边栏    ├───────────────────────────────────────────────┤
│ w-64↕48  │                                               │
│ 图标导航  │        内容区（min-h-0 flex-1，Tab 保活）      │
│          │                                               │
├──────────┴───────────────────────────────────────────────┤
│ StatusBar (h-7)：状态 · 推流 · LLM · TTS · 评论接入       │
└──────────────────────────────────────────────────────────┘
```

关键约定（照 TermPilot 实证过的做法）：

- `titleBarStyle:'hidden'` + titleBarOverlay + 自绘 DragStrip（win32 右留 138px）
- 侧边栏自绘 div（不用 shadcn Sidebar fixed 布局，Electron 有重影）
- Tab 切换条件渲染保活，不卸载内容；单一 zustand store；`window.api.<域>.<方法>` preload 命名空间
- Tailwind 4 `@theme inline` + oklch 双主题，localStorage 缓存防启动闪白
- 右键菜单承载次要操作；空态居中提示；全局对话框挂根节点

页面：

| Tab | 内容 |
|---|---|
| 直播台 | 评论流 + 话术池队列（按话轮分组、角色色）+ 播报区（当前播报句级高亮 + 生成中预览 + 当前场景）+ 导演对话 + 切场景/接管/插话/急停 |
| 主播团 | 人设卡编辑（性格/口癖/禁区）、角色音色绑定、触发器管理、记忆浏览 |
| 知识库 | 商品资料包：文档/图片/表格上传解析 + FAQ + 剧本场景编辑器 |
| 场次 | 一场直播的完整配置：主播配置 + 知识范围 + 剧本 + BGM + 音色，一键切换 |
| 数据 | 评论/回复统计 + 事件时间线（现场发生了什么 → AI 怎么反应的，可回放复盘） |
| 设置 | 模型/TTS/推流/接入 |

## 6. 主进程服务划分

```
src/main/services/
  AgentService.ts       pi 会话生命周期、事件流桥接（text_delta → 提词器）
  SpeechPool.ts         话术池：排序/预合成窗口/去重/限流/时效/持久化
  PlaybackEngine.ts     池的唯一消费者，音频引擎驱动
  EventBus.ts           事件总线 + EventRegistry
  TriggerRuntime.ts     触发器：过滤/聚合/节流/冷却/预算/三种模式
  AssistantService.ts   感知层小模型 Agent（评论分析/情报/氛围）
  MemoryService.ts      观众画像/场次摘要/agent 笔记本
  KnowledgeService.ts   资料包解析与检索
  PersonaService.ts     人设卡 CRUD + systemPrompt 组装
  TtsService.ts         火山/百炼双通道（搬迁）
  BroadcastService.ts   FFmpeg 混音推流（搬迁）
  CommentGateway.ts     PipeSDK 评论接入（搬迁）
  StorageService.ts     node:sqlite + safeStorage
src/shared/             纯类型 + IPC channel 常量
```

渲染进程音频引擎（WebAudio 三总线 + ducking + 真人接管 VAD）逻辑与框架无关，整体搬迁，Pinia → zustand。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| pi-agent 1.x 较新 API 变动 | 锁版本；AgentService 薄封装隔离 |
| LLM 自由发挥乱报价/违禁 | 价格只走 `check_price`；人设卡写禁区；敏感词后置过滤 |
| 单点故障（主播 Agent 挂） | 池存量 + filler + tool 模板撑场；会话树恢复 |
| 长场 token 成本 | 压缩 + 记忆注入预算 + 模型分层（感知层全 flash） |
| 实时性 | 流式按标点切句，成句即送合成；池缓冲吸收抖动 |
| 修订竞态 | `playing` 条目拒绝 revise，主播改下一条 |
| 评论接入合规 | PipeSDK 链路不经过服务端；对照 03-合规清单 |
