# TTS 选型调研：本地部署 vs 在线服务

## 1. 结论先行

**推荐"在线为默认、本地为可选"的混合架构：**

- **默认（MVP）：火山引擎豆包语音在线 API** —— 与抖音同生态、声音克隆秒级、首包延迟 <300ms、商用授权清晰、对店家电脑零要求。
- **可选（高级版）：本地 CosyVoice 2 Sidecar** —— 面向有 GPU 的用户或注重隐私/长期成本的客户，启动时自动检测硬件，达标才开放开关。
- 软件内通过统一 `TTSProvider` 接口隔离，用户无感切换。

## 2. 在线服务对比

| 服务 | 首包延迟 | 声音克隆 | 情感控制 | 成本 | 商用合规 | 适配度 |
|------|---------|---------|---------|------|---------|--------|
| **火山引擎豆包语音** | <300ms（流式） | 秒级克隆，约 150 元/年/音色 + 调用费，2 万次免费额度 | 指令式，强 | 中 | 授权链路清晰 | ★★★★★ 字节系，和抖音直播生态天然契合 |
| 阿里云 CosyVoice 商用版 | ~300ms | 支持 | 支持 | 按调用量 | 清晰 | ★★★★ |
| 微软 Azure TTS | 300–500ms | 定制音色需审核、周期长 | SSML 风格 | 偏高 | 清晰 | ★★★ |
| ElevenLabs | ~300ms | 效果好但中文一般 | 强 | 高（美元结算） | 清晰 | ★★ 中文场景不推荐 |

火山引擎参考：首包 <300ms、克隆秒级、150 元/年/音色、2 万次免费调用（见文末来源）。

## 3. 本地方案对比（开源）

| 模型 | 克隆样本 | 流式首包 | 硬件要求 | 中文效果 | 特点 |
|------|---------|---------|---------|---------|------|
| **CosyVoice 2**（阿里） | 3 秒 | **<150ms**，原生流式 | GPU 4–6GB 显存（CPU 可跑但慢，不适合实时） | 优秀 | 支持 `[happy]` 等情感指令、跨语言克隆；Flow Matching 架构 |
| GPT-SoVITS v4 | 5 秒零样本 / 1 分钟微调 | 非流式为主（需自行切块流式化） | CPU 可跑，GPU 更佳 | **中文最强之一** | 生态活跃、整合包多；长文本稳定性一般 |
| Fish Speech | 10 秒级 | 支持流式 | GPU 建议 6GB+ | 优秀 | 多语言，自然度好 |
| IndexTTS-2（B站） | 秒级 | 支持 | GPU | 优秀 | 情感控制强，较新 |

## 4. 本地 vs 在线决策矩阵

| 维度 | 在线 API | 本地部署 |
|------|---------|---------|
| 用户硬件门槛 | 无 | 需要 N 卡 4GB+ 显存，店家电脑多数不达标 |
| 延迟稳定性 | 稳定 <300ms，依赖网络 | 150ms 但受本机负载影响 |
| 长期成本 | 随调用量增长（日播 4h ≈ 可观费用） | 一次性硬件成本，之后免费 |
| 部署复杂度 | 填 API Key 即用 | 需分发 Python 环境 + 模型（2–5GB），打包/更新复杂 |
| 隐私 | 文本出域 | 全本地 |
| 商用授权 | 服务商兜底 | 开源协议自审（CosyVoice 为 Apache-2.0，可商用） |
| 声音克隆合规 | 平台要求本人授权验证（更合规） | 自行把关，需产品层做授权确认 |

**决策依据**：目标客户是"不会直播的企业和店家"——他们的电脑大多没有独显，运维能力弱。所以**在线必须是默认**；本地是为大客户/代理商准备的成本优化项。

## 5. 落地架构

```
                ┌─────────────────────────────┐
                │        TTSProvider 接口      │
                │  synthesize() / stream()    │
                └───────┬───────────┬─────────┘
                        │           │
              ┌─────────▼──┐   ┌────▼─────────────┐
              │ 火山引擎    │   │ CosyVoice2 Sidecar│
              │ HTTP/WS SDK│   │ Python FastAPI    │
              └────────────┘   │ localhost:9880    │
                               └──────────────────┘
```

- **预合成场景**（话术脚本）：两种 provider 都支持，结果缓存到本地音频库，重复开播零成本。
- **实时回复场景**：必须流式。在线走火山 WebSocket 流式接口；本地走 CosyVoice2 流式推理（首包 150ms）。
- **故障降级**：本地 provider 崩溃时自动切在线（若配置了 Key），并 toast 提示用户。
- **声音克隆流程统一**：无论哪种 provider，克隆向导都要求用户勾选"本人授权"确认，保留授权记录——这是合规底线。
