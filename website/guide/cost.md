# 费用与选型

小云播客坊不收费。持续支出只有两笔：语言模型 tokens 和语音合成字符，都由你在「设置」里自己接入、自己付账。

## 钱花在哪

| 花在哪 | 谁收费 | 计费口径 | 说明 |
| ------ | ------ | -------- | ---- |
| 语言模型（导演的脑子） | 你在「设置 → 语言模型」接入的服务商 | tokens（输入 / 输出 / 缓存命中） | 写稿、回评论、查知识库、上下文压缩都走这条 |
| 语音合成 | 你在「设置 → 语音合成」接入的服务商 | 合成出去的字符数 | 火山按字符，百炼按字符和模型档位，口径以控制台为准 |
| 声音克隆 | 同一家 TTS 服务商 | 复刻音色与克隆额度 | 火山复刻走后付费音色，音色库界面写明「首次正式合成即转正收费」 |
| 小云播客坊本体 | 不收费 | — | MIT 协议，源码在 [GitHub](https://github.com/xy200303/yuncast) |
| 本地那些功能 | 不收费 | — | 导出 MP3/WAV、混音、场次留档、统计都在本机跑 |
| 推流 | 不收费 | — | 直推用的 FFmpeg 随安装包分发；伴侣模式只出声音 |
| 平台连接器 | 平台方 | 以平台为准 | 抖音「直播数据助手」是单独的小软件，小云播客坊不为此计费，主程序里也没有平台 SDK |

音频文件存在你自己的用户数据目录（Windows 是 `%APPDATA%\YunCast\blobs`），占本机磁盘，不占服务商的空间。

::: tip 应用不折算金额
用量看板只记 tokens 和字符数，不乘单价折成钱。早期版本的「模型单价」录入已经停用，看板也不显示金额。想知道花了多少，拿看板里的量乘服务商控制台的单价。
:::

## 怎么估

两笔钱各有一个能算的入手点：token 由对话轮次和上下文长度决定，字符数由播出时长决定。

### 语言模型：看唤醒次数和上下文

```
一场的输入 tokens ≈ 唤醒次数 × 每次请求带的上下文规模
一场的输出 tokens ≈ 唤醒次数 × 单次回复长度
```

输入是大头：每次唤醒都要把整份上下文重发一遍——系统提示、节目配置、知识库片段、近期对话。

唤醒次数有硬帽兜着：事件驱动的唤醒和触发器派发在引擎里都是**每分钟最多 6 次**，你在界面上看不到这两个数，也改不了。两小时跑满也就 720 次，那是天花板不是常态。你在导演面板里主动问话不占这两个额度。

### 语音合成：看播出时长

```
字符数 ≈ 播出秒数 × 4.5
段数   ≈ 播出秒数 ÷ 桥段时长
```

4.5 字/秒是程序自己把字数折成时长的系数（「合成声音」弹窗里的「约 X 分钟」就是它算的）。写作规范里一个桥段是 30–90 秒的连续讲述、150–350 字，所以段数和字数能互相验算。

| 场景（粗估） | 出声时长 | 段数 | TTS 字符 |
| ------------ | -------- | ---- | -------- |
| 一场 2 小时几乎不空场 | 约 2 小时 | 100 段上下 | 3 万字上下 |
| 一场 2 小时、互动空档不少 | 1.5 小时上下 | 60–90 段 | 2 万字上下 |
| 一期 10 分钟预制播客 | 10 分钟 | 10–20 段 | 2700 字上下 |

有循环重播、有留白，实际比这少。三种播出方式（现场发挥 / 边播边准备 / 全部做好再播）的总字数差别不大，区别在于改稿之后要重合成多少。

拿到字符数之后乘服务商控制台的单价，就是这一场的 TTS 账。

## 用量在哪看

全在「统计 → 用量」这一页：四张卡片（今日 / 累计 · 大脑 / 语音）、近 30 天趋势、按节目分布、最近 100 条明细。

读这几个数要注意口径：

- **大脑用量**按服务商回报的真实 usage 记；服务商没回报 usage 的，按输出字符数 ÷ 4 估算，明细里标「估算」。
- **语音合成**按真正打接口的合成记字数。命中本地缓存的那次不打接口，也就不进看板。
- **归组口径**是请求发生时的「当前节目」，没选节目就记成「—」。你在导演面板里闲聊的用量，也算在当时选中的那个节目名下。
- **用途列**分 `直播对话 / 写稿 / 上下文压缩`。最后一项是自动压缩旧消息时发的摘要请求，它同样是一次真实调用。
- 页面 10 秒自动刷一次，直播在跑时数字自己往上走。只有节目维度，没有场次级的 tokens 明细——要对到某一场，用明细表的时间和[场次记录](/guide/interface)的起止时间对。

## 怎么选

| 你要做的事 | 建议 | 为什么 |
| ---------- | ---- | ------ |
| 中文带货话术 | OpenAI 兼容通道 + 服务商的中档对话模型 | 话术对措辞要求不极端，贵在长上下文和高频唤醒，不在单次智力 |
| 长时段直播 | 挑上下文窗口大、缓存便宜的型号，并在模型行的扳手里把「上下文窗口」填准 | 窗口填小了会压缩得更勤，摘要本身也要钱 |
| 预制播客 / 有声书 | 稿子定稿后一次合成，用便宜模型写稿 | 文稿一改，对应音频会标成「文稿已修改」要重新合成；先把价格口径核完再动笔 |
| 双人播客 | 火山 Podcast 双人播客模型（整期一次合成，按总轮次字符计费） | 轮次稿按主持人 A/B 交替，整期韵律更连贯；普通 TTS 与克隆音色也能当主持人 |
| 要店家自己的声音 | 音色库里克隆一个 | 样本要 10–30 秒干净人声、无伴奏；火山复刻提交后秒级完成，百炼要公网可访问的样本地址 |
| 内网或本地模型 | 「自定义接口」填本地地址（Ollama / vLLM / LM Studio，示例 `http://127.0.0.1:11434/v1`） | 本地模型不产生 API 费用；中间加了网关或代理，那笔账你自己算 |

同一个服务商内部还有档位之分——火山是 Seed-TTS 2.0 / 1.0 与声音复刻，百炼是 Qwen-TTS、Qwen-Audio、CosyVoice 几个系列，名字里带 Flash 和 Plus 的档位单价不同。差价以控制台价目为准，选之前先用音色库的「试听」听一遍。

## 怎么省

浪费只出在两处：同一段音频合成两次，和没事也叫一次大脑。

### 复用已经合成过的音频

- 缓存键把服务商、接入、模型、音色、参数、文本一起算进去。同一句话配同一个音色再合成一次，直接取本地文件，不打接口也不进用量。循环重播、重复试听都走这条路。
- 预制节目（「全部做好再播」）的音频是长期资产，循环播出反复用同一批文件，不再重新合成。
- 点「生成节目音频」或「提前合成全部」时，已经就绪而且文稿没改过的单元会跳过——弹窗里的「本次合成 N 段」只算剩下的。
- 现成的录音可以导入：节目卡「底稿库」→ 音频进度区，把 mp3 / wav / m4a 挂到某个单元上，这一段跳过合成。
- 改了文稿，对应的预制音频会标成「文稿已修改」，文件不删；把文稿改回原样，它自己恢复成就绪，不用重新合成。
- 整场导出成 MP3/WAV（分章或合并、响度归一）之后，拿这份成品去音频平台发布，不用再合成一遍。

::: warning 缓存不是永久保险
没有任何引用的缓存音频过 7 天宽限期会被回收；缓存档总量超过 500MB 时按最久未用逐出（可用环境变量 `AGENT_ANCHOR_AUDIO_CACHE_MB` 调）。已经挂在节目或场次上的音频有引用，不会被回收，但被回收过的缓存音频再合成会重新打接口。
:::

### 别开用不上的触发器

内建触发器分两类：送礼感谢、点赞里程碑这类只往话术池塞一句固定话术，不叫大脑；欢迎新人、冷场自救、价格变动提醒这类每次触发都是一次真实请求。内建的「整点带节奏」默认就是关的——定时叫醒是「没事也运行」的 token 大头。

无人值守的轮播场可以关掉主播看的直播间动态：直播台底部「⋯ → 自动响应」里关掉「让主播看到直播间动态」，评论、礼物、进场一概不派给主播。这个开关播出中也能改，改完立刻生效，不用下播。

底稿库还有个内部上限（200 段）当成本闸：写满会拒，开播后池子空了就循环已有底稿，音频复用，不重新合成。

### 上下文与提示词

- 把「上下文窗口」填准（「设置 → 语言模型」模型行右侧扳手 → 高级参数）。对话快涨满窗口时会自动压缩旧消息，阈值是「窗口 − min(16k, 窗口的 40%)」。
- 导演面板输入框右边那个圆环是上下文仪表，悬停显示「导演的短期记忆已用 Z%」。这是输入成本最直观的一个读数。
- 「设置 → 导演手册」里模板写得越长，每次请求的输入越大。改完要重开会话才生效。

### 克隆音色之前想清楚

克隆音色的「试听」是真合成一句「你好，我是 XX，欢迎来到直播间。」——第一次调用就产生一笔很小的合成。样本不合格会白折腾一次训练，所以按 10–30 秒干净人声准备，一次过。

火山的复刻音色按后付费模式走，音色库界面写的原话是「首次正式合成即转正收费，试听 7 天未正式调用会被删除」。是否另收克隆费用，以服务商控制台为准。
