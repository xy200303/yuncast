# 10 · 节目化改造最终方案

> 状态：**方案定稿，尚未实施**。
>
> 原则：基于现有场次、剧本、文稿、话术池、主播 Agent、TTS 抽象、播放引擎和播控台增量升级；不引入播放记录、独立生产工作区、任务中心、交付物中心等非必要概念。
>
> 前置：节目与主播已解耦。节目负责内容和规则，当前主播 Agent 可随时接手。

---

## 1. 产品目标

将现有 AI 直播系统升级为**平台无关的 AI 声音节目工作台**。

一个节目可以：

- 由 Agent 生成、续写和修改文稿；
- 即兴播出、边播边合成或全部预制后播放；
- 接收直播间评论、礼物、关注和业务事件；
- 在本机播放，也可以进入现有 RTMP 音频管线；
- 导出为音频文件，上传到任意内容平台；
- 用于直播口播、播客、有声书和广播剧。

用户只需要理解：

```text
这是什么内容？
怎么播？
哪些事件需要通知主播？
播放还是导出？
```

## 2. 核心边界

### 2.1 节目决定什么

- 内容类型；
- 播出方式；
- 剧本、文章、章节和知识范围；
- 哪些事件触发器在本节目启用；
- 播完停止还是循环；
- 预制节目使用哪个 TTS 模型；
- 当前文稿和已生成音频。

### 2.2 主播 Agent 决定什么

- 是否回应直播间动态；
- 回应哪一条；
- 逐条回答还是合并回答；
- 立即插播还是等待当前内容结束；
- 使用文字回复还是语音回复；
- 如何表达、使用什么人格、模型和音色；
- 是否忽略无价值、重复或恶意事件。

### 2.3 播放引擎决定什么

- 当前播放项；
- 顺序、暂停、跳过和循环；
- 音频衔接；
- 插播优先级；
- 将音频送入主进程 AudioPipeline。

### 2.4 全局输出决定什么

- 系统扬声器；
- 由直播伴侣采集系统声音；
- 已开启的 RTMP 混音输出。

节目不保存“抖音、快手、B 站”等平台字段。对节目而言，输出始终只是音频。

## 3. 概念升级

| 当前名称 | 新名称 | 说明 |
|---|---|---|
| 场次 | 节目 | 一份可编辑、可播放、可导出的声音内容 |
| 直播台 | 播控台 | 播放任何类型的节目，不限定直播口播 |
| 底稿/话术库 | 文稿 | 可以是段落、场景、章节或对话轮次 |
| 话术池 | 播出队列 | 实际等待播放的内容与音频 |
| 直播模式 | 删除 | 由内容类型、播出方式、事件规则分别表达 |
| 主播自动触发器 | 删除 | 触发器启用状态归节目 |
| 启动/结束场次 | 播放/结束节目 | 与平台无关 |

第一阶段可以保留内部类名 `LivePlan`、数据库表 `live_plans`，先完成产品语义和能力升级；代码重命名可以在功能稳定后统一处理。

## 4. 节目配置

节目配置只保留四组。

### 4.1 基本信息

```text
节目名称
内容类型
主题与节目说明
剧本 / 文章 / 章节
知识库范围
```

#### 内容类型

```ts
type ContentType =
  | 'live'       // 直播口播
  | 'podcast'    // 播客
  | 'audiobook'  // 有声书
  | 'drama'      // 广播剧
```

内容类型只影响：

- Agent System Prompt；
- 写稿任务书；
- 文稿结构和界面文案；
- 默认播出方式；
- 主播表达规范。

内容类型不限制播放、推流或导出。有声书、播客和广播剧均可在直播软件中播放；直播口播也可以提前全部合成后导出。

#### 同一底层结构的 UI 文案

底层继续复用 `Script / Scene`：

| 内容类型 | Script 显示名 | Scene 显示名 |
|---|---|---|
| 直播口播 | 节目脚本 | 场景 |
| 播客 | 本期大纲 | 环节 |
| 有声书 | 书稿 | 章节 |
| 广播剧 | 剧本 | 场/幕 |

### 4.2 播出方式

```ts
type BroadcastMode =
  | 'improvised' // 即兴播出
  | 'rolling'    // 滚动播出
  | 'prepared'   // 预制播出
```

#### 即兴播出

> 无固定底稿，由主播 Agent 根据导演指令和直播间动态现场说。

适用：

- 交互直播；
- 陪聊和问答；
- 临场主持。

运行规则：

- 不要求底稿；
- Agent `say` 后实时 TTS；
- 无评论和导演指令时可以不说；
- Agent 自行决定是否延续话题；
- 播出队列只保存即将说出的内容。

#### 滚动播出

> 已有底稿，一边播放前面的内容，一边提前合成后面的内容。

适用：

- 带货直播；
- 产品宣讲；
- 长时间循环节目；
- 需要随时改稿或插播的节目。

运行规则：

- 开始时只要求前几段音频就绪；
- 后台维持固定合成窗口，第一版默认 5 段，不暴露给普通用户；
- Agent 可以修改未播放内容；
- 直播间回复可以插播；
- 播完后停止或循环。

#### 预制播出

> 先将节目音频全部合成完成，再播放或导出。

适用：

- 有声书；
- 播客；
- 广播剧；
- FM 风格节目；
- 文章朗读。

运行规则：

- 文稿确认后批量合成；
- 必需音频全部就绪后才能正式播放；
- 可以直接导出；
- 支持导入外部音频；
- 不启用低水位补货和现场续写。

### 4.3 事件规则

节目主表单只显示：

```text
事件规则    已开启 5 项  >
```

点击进入栏内配置页，只选择是否启用：

```text
直播间事件
[x] 欢迎观众进场
[x] 感谢关注
[x] 感谢礼物
[x] 将评论提供给主播
[x] 将提问提供给主播

节目状态
[x] 播出队列为空
[x] 长时间没有新互动
[x] 章节播放完成
[ ] 节目即将结束

业务事件
[x] 商品价格变化
[ ] 商品库存变化
```

普通用户不配置评论批处理秒数、触发器冷却时间或 Prompt 模板。高级参数保留在全局触发器库。

### 4.4 播完以后

```ts
type FinishMode = 'stop' | 'loop'
```

只显示：

```text
播完停止
循环播放
```

即兴播出不显示该项；滚动播出和预制播出显示。

## 5. 事件与互动

### 5.1 主播卡不再配置触发器

主播卡只保留：

```text
姓名
人格
背景
口癖
禁区
语言模型
音色
多角色能力
```

移除：

```text
自动触发器
欢迎规则
冷场规则
互动模式
节目类型
```

同一个主播可以主持不同节目；节目切换不会迫使用户创建多个主播版本。

### 5.2 全局触发器库 + 节目启用项

全局触发器库继续复用现有 `triggers` 表和 `TriggerRuntime`，负责定义：

- 事件条件；
- 默认任务模板；
- 冷却和防刷；
- 事件优先级。

节目只保存：

```ts
enabledTriggerIds: string[]
```

节目不复制触发器定义。

### 5.3 直播间动态收件箱

评论、礼物、关注和进场事件先进入直播间动态收件箱，不直接产生固定回复：

```text
评论 / 礼物 / 关注 / 进场
            ↓
      直播间动态收件箱
            ↓
  有新动态时合并唤醒 Agent
            ↓
Agent 读取当前积压的全部新动态
            ↓
自主决定逐条、合并、延迟或忽略
```

系统只负责收集和防止并发轰炸，Agent 决定回应语义。

如果没有新动态：

- 不唤醒 Agent；
- 不创建无意义的 LLM 请求；
- 有底稿的节目继续播放；
- 即兴节目可以自然停顿。

### 5.4 触发器不直接生成固定对外话术

内容类触发器向 Agent 发送事件任务，例如：

```text
系统：用户“小明”送出了礼物。
```

Agent 决定立即感谢、稍后感谢或忽略。

安全类和纯控制类触发器可以保留确定性操作，但不能绕过 Agent 擅自生成对外内容。

## 6. TTS 模型能力

### 6.1 特殊能力仍属于 TTS 模型

火山 PodcastAPI 在产品层是一个特殊 TTS 模型，不新增“Podcast 后端”概念。

```ts
type TtsModelKind =
  | 'standard'  // 普通单人 TTS
  | 'longform'  // 原生长文合成
  | 'podcast'   // 双人播客专用模型

interface TtsModelCapabilities {
  kind: TtsModelKind
  input: 'text' | 'longText' | 'dialogueTurns'
  output: 'file' | 'stream'
  minSpeakers: number
  maxSpeakers: number
  supportsCloneVoice: boolean
  supportsResume: boolean
  supportsTimestamps: boolean
  maxTextChars?: number
  maxCharsPerTurn?: number
}
```

火山模型示例：

```ts
{
  id: 'volc-podcast-v3',
  label: 'Podcast 双人播客',
  capabilities: {
    kind: 'podcast',
    input: 'dialogueTurns',
    output: 'stream',
    minSpeakers: 2,
    maxSpeakers: 2,
    supportsCloneVoice: true,
    supportsResume: true,
    supportsTimestamps: true,
    maxTextChars: 10000,
    maxCharsPerTurn: 300
  }
}
```

### 6.2 节目只选择 TTS 模型

节目不保存：

```text
wholeBackend
火山 PodcastAPI 开关
Podcast 后端
```

只保存：

```ts
ttsConnectionId: string
ttsModelId: string
```

界面根据模型能力自动变化。

#### 普通 TTS 模型

显示：

```text
主播音色
逐段或整章
语速、音调、演绎指令
```

#### Podcast 模型

显示：

```text
主持人 A 音色
主持人 B 音色
开场音乐
结尾音乐
语速
```

隐藏逐段/单人音色等无关字段。

### 6.3 模型与播出方式的能力校验

| 播出方式 | 模型要求 |
|---|---|
| 即兴播出 | `kind=standard` 且支持流式输出 |
| 滚动播出 | `kind=standard`，按段生成 |
| 预制播出 | 普通、长文或 Podcast 模型均可，按内容结构选择 |

双人播客要求：

```text
contentType = podcast
broadcastMode = prepared
model.kind = podcast
model.maxSpeakers >= 2
```

### 6.4 统一合成请求

```ts
type TtsSynthesisRequest =
  | {
      type: 'text'
      text: string
      voiceId: string
      instruction?: string
      rate?: number
      pitch?: number
    }
  | {
      type: 'podcast'
      turns: PodcastTurn[]
      speakers: [string, string]
      useHeadMusic: boolean
      useTailMusic: boolean
      speechRate?: number
    }

interface PodcastTurn {
  speaker: string
  text: string
}
```

普通 HTTP/SSE、原生长文、火山 WebSocket v3 协议由各模型适配器实现，上层节目只调用统一 TTS 服务。

### 6.5 Agent 与 PodcastAPI

Agent 生成结构化双人轮次稿：

```ts
[
  { speaker: 'host-a', text: '今天我们聊聊 AI 语音直播。' },
  { speaker: 'host-b', text: '最近实时互动确实很热。' }
]
```

角色音色映射后转换为火山 `action=3` 的 `nlp_texts`。内容生成权始终在本地主播 Agent，火山模型只负责专业双人音频合成。

WebSocket 鉴权、二进制帧、360/361/362/363/154/152 事件、断点续传和错误码全部封装在火山 Podcast 模型适配器内部。

## 7. 合成方式

合成方式不在主节目配置中全部展开，而是由播出方式和所选 TTS 模型决定。

### 7.1 即兴播出

自动使用实时流式合成，不显示额外选项。

### 7.2 滚动播出

自动使用逐段合成和现有合成窗口。第一版固定提前准备 5 段。

如果模型支持前文上下文，可以使用前一段尾句改善连贯性；不支持则自动降级。能力必须由模型 manifest 明确声明，不能假设所有 TTS 都支持。

### 7.3 预制播出

根据模型能力显示：

- 普通逐段预制；
- 原生长文合成；
- Podcast 双人合成。

分段生成后拼成完整文件只能称为“分段合成并拼接”，不能承诺获得原生长文模型的连续表演效果。

### 7.4 外部音频

预制节目支持为场景/章节挂载外部音频：

- 跳过 TTS 合成；
- 进入试听、播放和导出流程；
- 允许与 AI 合成章节混排。

## 8. 播放与输出

### 8.1 节目只有两个主输出按钮

```text
[播放] [导出]
```

不再区分“播放”和“开始直播”。

### 8.2 播放

节目音频进入现有主进程音频管线：

```text
节目音频
   ↓
AudioPipeline
├─ 系统扬声器
├─ 直播伴侣采集系统声音
└─ 已开启的 RTMP 混音输出
```

如果 RTMP 正在输出，播控台显示：

```text
● RTMP 输出中
```

不显示具体平台。

### 8.3 导出

节目内直接导出已生成音频：

- 当前段落；
- 当前章节；
- 全部章节；
- 分章文件；
- 合并为一个文件。

第一版只提供：

```text
MP3 / WAV
分章导出 / 合并导出
输出目录
文件名模板
响度归一开关
```

ID3、True Peak、位深和平台规格等专业字段后续增加，不阻塞第一版。

## 9. 数据结构最小改造

### 9.1 Program（由 LivePlan 升级）

```ts
interface Program {
  id: string
  name: string
  theme: string

  contentType: ContentType
  broadcastMode: BroadcastMode
  finishMode: FinishMode

  allowLiveEvents: boolean
  enabledTriggerIds: string[]

  ttsConnectionId: string
  ttsModelId: string

  scriptId: string | null
  knowledgeScope: PlanKnowledgeScope
  currentSceneIdx: number

  createdAt: number
  updatedAt: number
}
```

`allowLiveEvents` 控制是否将直播间动态提供给 Agent；触发器只处理明确启用的自动化事件。

### 9.2 删除的旧字段和概念

开发阶段不保留兼容双轨：

```text
LivePlan.modeId
modes 表及直播模式 UI
主播卡中的 triggerIds
preparedSynthMode
wholeBackend
平台选择字段
```

`modes.promptModule` 的节目语义改由：

```text
contentType + broadcastMode
```

生成。

`modes.wiring` 改由：

```text
allowLiveEvents + enabledTriggerIds
```

决定。

### 9.3 继续复用的现有结构

```text
Script / Scenes
Utterances
SpeechPool
SpeechItem
PlaybackLoop
AgentService
TtsService
LaunchService
EventBus
TriggerRuntime
知识库
音频与推流管线
```

### 9.4 预制音频存储

为避免引入复杂任务中心，第一版可以在现有 Scene/Utterance 结构上记录：

```ts
interface RenderedAudioRef {
  audioPath: string
  durationMs?: number
  status: 'pending' | 'synthesizing' | 'ready' | 'failed'
  voiceOrModel: string
  external?: boolean
  error?: string
}
```

- 逐段音频继续存 `Utterance.audioPath`；
- 整章/整期音频挂在对应 Scene；
- Podcast 整期可使用一个 Scene；
- 应用重启时 `synthesizing` 重置为 `pending` 或 `failed`，允许用户重试。

不新增播放记录、Run、Deliverable、任务中心等用户不需要的对象。

## 10. Agent 写稿

Agent 继续通过现有对话区和工具修改文稿。

| 内容类型 | 默认任务书 |
|---|---|
| 直播口播 | 场景化分段话术，可滚动补充 |
| 播客 | 完整一期结构；单口或双人轮次 |
| 有声书 | 按章节写作，保持人物和旁白一致 |
| 广播剧 | 角色台词、旁白和音效提示 |

| 播出方式 | 对 Agent 的约束 |
|---|---|
| 即兴 | 不要求底稿，读取现场动态后自主表达 |
| 滚动 | 优先使用已有文稿，必要时补充或修改未播内容 |
| 预制 | 先完成整份文稿，审核后再开始批量合成 |

System Prompt 由以下内容组合：

```text
主播人格
+ 节目内容类型
+ 播出方式
+ 当前节目/场景/章节
+ 启用事件规则
+ 知识库范围
```

## 12. 需要制作的最终 UI 原型

实施前仅制作 5 组审核原型，不扩散页面数量：

1. **节目库**：内容类型、播出方式、状态和主操作。
2. **节目配置**：基本信息、三种播出方式、事件规则摘要、条件化 TTS 模型字段。
3. **事件规则栏内页**：三组触发器开关。
4. **播控台**：通过状态切换展示即兴、滚动和预制三种自动布局；不出现“几张脸”切换器。
5. **预制节目播放 + 导出弹窗**：章节、长音频播放器和最小导出字段。

原型必须沿用现有 shadcn/Radix 暖陶色、Lucide 图标、正文 13–14px 和现有对话样式；需要提供 1600×900 与 1366×768 PNG 供审核。

## 13. 实施路线

### P1 · 节目配置

- 场次产品语义改为节目；
- 增加 `contentType / broadcastMode / finishMode`；
- 增加 `allowLiveEvents / enabledTriggerIds`；
- 触发器从主播卡移到节目；
- 删除 `modes` 双轨；
- 更新节目库和节目配置 UI。

### P2 · Agent 事件收件箱

- 评论、礼物、关注和进场进入动态收件箱；
- 同一短时间窗口的事件合并唤醒 Agent；
- Agent 自主读取、忽略、合并、延迟和回应；
- 内容类触发器只通知 Agent，不直接输出固定话术。

### P3 · 三种播出方式

- 即兴播出复用实时 TTS；
- 滚动播出复用现有合成窗口和播出队列；
- 预制播出增加全部完成门禁、批量合成和外部音频导入；
- 补充模型能力校验。

### P4 · 播控台适配

- 根据 `broadcastMode` 自动适配中间区域；
- 即兴模式隐藏无意义的空底稿；
- 滚动模式保留可操作队列；
- 预制模式增加长音频进度、seek 和章节列表；
- 统一播放、暂停、导出和急停入口。

### P5 · 特殊 TTS 模型与导出

- 扩展 TTS Model Capability；
- 接入原生长文模型；
- 将火山 PodcastAPI 注册为 `kind=podcast` 的特殊模型；
- 实现节目内分章/合并导出。

## 14. 验收标准

### 节目配置

- 创建节目最多需要理解“内容类型、播出方式、事件规则、播完策略”；
- 普通用户看不到协议和后端工程术语；
- 不适用的 TTS 配置不会显示；
- 主播卡中不再出现触发器。

### Agent 互动

- 没有新动态时不会触发无意义 LLM 请求；
- 多条相似评论可由 Agent 合并回答；
- Agent 可以忽略无价值事件；
- 换主播不改变节目启用的事件规则。

### 播出

- 即兴节目无需底稿即可播放；
- 滚动节目可以边播边合成并插播；
- 预制节目全部音频就绪后可直接播放和导出；
- 节目播放能同时进入系统声音和已启用的 RTMP 管线；
- 节目不感知具体平台。

### TTS

- 普通、长文和 Podcast 模型统一出现在 TTS 模型体系中；
- 选择模型后 UI 按 capability 自动变化；
- 火山 PodcastAPI 的协议细节完全封装在模型适配器中；
- Agent 负责生成双人轮次稿，Podcast 模型只负责合成。

### UI

- 播控台不出现人工“三模式界面切换”；
- 节目设置主页面没有大量触发器按钮；
- 事件规则使用独立栏内页；
- 1366×768 下关键操作不被裁切；
- 所有关键状态同时使用文字和图标表达。

## 15. 最终产品模型

```text
节目决定：
- 是什么内容
- 即兴 / 滚动 / 预制
- 哪些事件通知主播
- 播完停止还是循环
- 选择哪个 TTS 模型

主播 Agent 决定：
- 是否回应
- 回应什么
- 什么时候回应
- 逐条还是合并
- 怎么说
- 使用自己的模型和音色

播放引擎决定：
- 当前播出队列
- 音频衔接
- 暂停、跳过和循环

全局音频管线决定：
- 系统出声
- 直播伴侣采集
- RTMP 输出

节目提供：
- 播放
- 导出
```

最终原则：**场次升级为节目，触发器归节目，回应决策归 Agent，特殊能力归 TTS 模型，输出保持平台无关。**
