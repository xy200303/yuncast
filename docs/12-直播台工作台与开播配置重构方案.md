# 直播台工作台与开播配置重构方案

> 状态：**方案待评审**（未动代码）
> 来源：甲方试用反馈（2026-10-18）
> 关联：`docs/10-节目化改造方案.md`（节目/编排模型）、`docs/11-段卡片播放与TTS真人化方案.md`（段卡片）

---

## 一、背景：甲方 5 条反馈

1. 切换节目时应当立刻显示当前话术稿——**全部**条目，已播的置灰；每条支持「从此处开始播」或「仅播此条」。
2. 状态混乱：合成失败被当成"没有话术"，进而触发 Agent 重新生成，陷入**合成死循环**。
3. 开播时才做主播 / 音色 / 语言的配置；现在是"先配主播 → 主播里再配音色"，层层嵌套。音色没声明支持泰语但语言选了泰语照样能播，太死板；另外有些模型**根本不存在**，需要与官方文档核对。
4. 跨境场景只有目标语言（泰语/英语），看不懂在播什么；生成话术时应同时产出**目标语 + 中文对照**。
5. 操作链条太长：资产一层套一层（主播绑音色、节目绑主播），希望**资产库只做静态描述**，直播时自由选择；节目不绑音色，节目只是内容载体与可复用内容；直播台要变成真正的工作台。

## 二、诊断：不是 5 个 bug，是 3 个结构问题

| 甲方感受 | 真实成因 |
|---|---|
| 切节目看不到稿、状态混乱 | 直播台目前是「播放器」不是「工作台」：切节目只换播放源，底稿全量从不展示，条目状态（已播/失败/跳过）没有出口 |
| 失败 → 以为没稿 → 重生成 → 死循环 | 失败条目**不进池、也不可见**；池空判定把"有失败"当成"真空"，于是触发补货；根因未消除，新稿同样失败，循环成立 |
| 主播→音色、节目→主播 层层嵌套 | 资产层在**互相绑定**：`personas.voiceId` 必选、`programs.personaIds` 是卡司；配置是"一层套一层"而不是"一次选完" |
| 音色不支持泰语也能播；模型不存在 | 语言在节目上、音色在主播上，两者**没有能力声明**，界面无法校验；模型清单硬编码，与官方文档脱节 |
| 跨境看不懂 | 话术只有目标语言一个字段，没有中文对照的位置 |

**结论：资产解耦；绑定前置到"本场"这一次操作；状态全部可见且可干预。**

## 三、目标与非目标

**目标**

- 资产（主播 / 音色 / 节目 / 素材）之间零引用，只做静态描述。
- 每次开播必经一次「直播配置」：语言、主播、音色、播出方式、音频策略一次选完。
- 直播台成为工作台：全量底稿可见、状态可见、可点播、可重试。
- 合成失败不再触发自动重生；有熔断。
- 外语节目天然带中文对照。

**非目标（本期不做）**

- 不改写稿质量与 agent 提示词的写作风格（只改它取语言/主播的方式）。
- 不做多机位、多路推流。
- 不做音色市场、跨账号共享。

## 四、新模型：三层解耦

```
资产层（静态描述，互不引用）
  主播卡   姓名 / 性格 / 口癖 / 背景 / 红线 / 说话风格        ← 去掉 voiceId
  音色     音色 id / 接入 / 模型 / 支持语言 / 风格指令 / 是否克隆
  节目     名称 / 主题 / 编排（场景序列） / 素材范围 / 底稿库   ← 去掉 personaIds
  素材     条目（正文 / 附件 / 链接）

会话层（唯一做绑定的地方：开播配置）
  节目（= 导入它的底稿库） + 主主播 + 该主播的音色 + 播出语言
  + 播出方式 + 互动开关 + 音频策略（复用 / 清空重合成）

运行时层
  话术队列（全量可见） / 条目状态机 / 双语对照 / 失败与重试 / 事件
```

要点：

- **节目只存底稿**（连同编排、素材范围）。节目里不再有"谁播""什么声音""什么语言"。
- 改了主播卡不影响任何节目；换音色不需要动主播卡；同一个节目换人播不需要重配。
- 音色是音色库里的独立资产，只在开播配置里被选中。

## 五、开播配置：点「启动节目」先弹窗，每次都要过一遍

### 5.1 流程

```
直播台 → 选节目（只导入底稿，不启动）
      → 点「启动节目」
      → 弹「直播配置」（4 步，一屏看完）
      → 预检（阻断项才拦）
      → 开播
```

**每次开播都必须经过这个弹窗**，不做"上次配置直接开播"的快捷路径——这是甲方明确要的"业务状态清晰"：这一场用什么人、什么嗓子、什么语言、读什么稿、用旧音频还是重合成，全部在开播那一刻确认并写进场次记录。字段可以**预填上次的值**（减少重复输入），但必须由人点确认；预填值不写回资产。

### 5.2 弹窗结构

```
┌ 直播配置 ──────────────────────────────────────────────────┐
│ 节目：治愈电台 · 深夜朗读        （底稿 12 条 · 中文）      │
│                                                            │
│ ① 播出语言   [中文 ▾]   （跨境选泰语/英语会提示对照）      │
│ ② 主播       [云溪 ▾]   ← 只列主播卡的静态人设             │
│ ③ 音色       [心理FM · 云溪 ▾]                            │
│              支持语言：中文 / 英文                          │
│              ⚠ 该音色未声明泰语，多数多语模型仍可读，建议先试听 │
│ ④ 播出方式   ( ) 一遍播完  (•) 循环返场  ( ) 播完停止        │
│ ⑤ 合成时机   (•) 预合成   ( ) 异步边播边合  ( ) 实时流式      │
│              主内容按此档；互动回复固定走实时流式              │
│ ⑥ 音频策略   (•) 复用现有音频  12 条就绪 / 0 条需合成         │
│              ( ) 清空音频重新合成  预计 3 分 20 秒 · 约 12 次调用 │
│              [试听这一段]                                  │
│                                                            │
│ 互动：☑ 读评论区  ☑ 突发事件交给导演                        │
│                                  [取消]  [确认开播]         │
└────────────────────────────────────────────────────────────┘
```

### 5.3 音频策略（甲方第 5 条的后半句）

点开播时给两个选项，二选一，默认「复用现有音频」：

| 选项 | 行为 | 界面上要写清楚 |
|---|---|---|
| **复用现有音频** | 就绪的段直接播；只有缺失/已失效的段才补合成 | 「12 条就绪，开播即出声；3 条待合成会边播边补」 |
| **清空音频重新合成** | 先清空该节目全部已合成音频，按当前音色/语言全量重合成，**合成完才开播** | 「将清空 15 段音频，预计 3 分 20 秒、约 15 次 TTS 调用；期间不能开播」 |

- 清空是显式动作，带二次确认（输入段数或勾选「我知道会重新计费」）。
- 选「清空重合成」时，进度在弹窗里显示（N/M 段），可取消；取消后回到"复用现有音频"。
- 单个条目也可以单独「清空这条音频」，不要求整场重来。

### 5.4 合成时机：三种，不是两种

甲方补充的「实时交互形式」要单独成一档。合成时机与音频策略是两个问题（前者是**什么时候合成**，后者是**用不用旧音频**）：

| 档 | 行为 | 首字延迟 | 适用 | 代价 |
|---|---|---|---|---|
| **预合成** | 开播前整段合成完再出声 | 0（已就绪） | 有声书、宣讲、播客、逐字稿 | 改一个字就要重合成 |
| **异步边播边合** | 播 A 的同时合成 B、C，保持 N 段提前量（N 可配，默认 3） | 只在补货跟不上时才等 | 带货、循环话术、长播 | 需要水位/缓冲管理，补货慢于消耗会冷场 |
| **实时流式** | LLM 边说边分句，**每句立刻合成立刻播**（首句优先），支持打断 | 0.8–2 秒 | 互动直播、回评论、突发应对 | 逐句合成语气不如整段连贯；依赖模型流式能力；并发与成本更高 |

**关键设计：合成时机是按「车道」定的，不是全场一个开关。**

```
车道 A · 主内容（话术稿）     → 预合成 或 异步边播边合   （由本场配置决定）
车道 B · 互动回复（评论/进场）→ 固定实时流式，永不排队等预合成
车道 C · 突发/口播提醒        → 实时流式（可插队，最高优先级）
```

- 车道 B/C 的实时合成**不占用水位、不进预合成队列**；否则回一条评论要等 30 秒补货，体验就废了。
- 三条车道共用一路音频输出，靠优先级与 duck（压低主音量）协调：互动进来时主话术淡出→回复→恢复。
- 播放条上给每条标出它走的是哪档（`预`/`异步`/`实时`），实时车道显示当前首字延迟（如 `1.2s`），出问题一眼能看出是"模型慢"还是"网络慢"。
- 实时档失败的降级：连续 2 句合成失败 → 用预置短句（「稍等，我看看」）兜住 + 提示卡，绝不静默。

**依赖项（需要核对官方文档后再定档位）**：百炼 `qwen3-tts-flash` / CosyVoice 系列、火山 `seed-tts` 系列的**流式合成接口与并发上限**。清单核对（见第 8 节）时一并确认：是否支持流式、首包延迟、并发连接数、是否支持语气指令。

### 5.5 审核与阻断规则

| 检查项 | 级别 |
|---|---|
| 节目没有底稿 | 阻断：「先去写稿，或勾选现场发挥」 |
| 音色模型 id 不存在 / 接入已删 | 阻断，给替代项 |
| 语言不在音色声明支持里 | **警告**（可继续，建议试听） |
| 导演大脑没配 | 警告：播照常，但没有智能补货/互动 |
| 评论区未接入 / 推流未配 | 警告（按现有预检逻辑） |

## 六、直播台工作台布局

```
┌──────────────────────────────────────────────────────────────┐
│ 本场：治愈电台·深夜朗读   云溪 / 心理FM·云溪   中文   循环返场  │ ← 本场快照，只读，点开可看详情
├───────────────────────────┬──────────────────────────────────┤
│ 话术稿（全部 15 条）        │  当前播出                        │
│ ✅ 01 开场白         已播   │   目标语大字                     │
│ ✅ 02 今天这一期     已播   │   中文对照（小字，可折叠）        │
│ ▶  03 有一年夏天     在读   │   [从此处播] [仅播此条] [跳过]    │
│ ⏳ 04 …              合成中 │                                  │
│ ⚠ 05 …              失败 ▸ │  ──────────────────────────────  │
│    原因：音色不支持泰语      │  导演对话                        │
│    [重试] [换音色] [跳过]   │                                  │
│ ⬜ 06 …              待播   │                                  │
├───────────────────────────┴──────────────────────────────────┤
│ ▶ 03/15  ├────●─────┤ 🔊 ──  ⏸ 暂停  ⏭ 跳过  结束本场         │
└──────────────────────────────────────────────────────────────┘
```

- **切节目 = 立刻列出该节目全部底稿**（不是只列未播的）。已播置灰、在读高亮、失败带原因。
- 条目动作（hover 或右键）：**从此处开始播**（排到队首，原顺序不变）、**仅播放此条**（插播，播完回到原位）、**重试合成**、**跳过**、**编辑文本**、**重新翻译**。
- 顶栏是「本场快照」，只读；要改配置就"结束本场 → 重新开播 → 再过一次配置弹窗"。

## 七、状态机与防死循环

```
未合成 → 合成中 → 就绪 → 在读 → 已播
                     ↘ 失败（原因 + 重试次数）→ 重试 / 跳过 / 换音色
```

三处断路器：

1. **失败可见**：失败条目留在列表、标红、带原因（音色不支持语言 / 401 鉴权失败 / ffmpeg 不可用…），而不是从界面消失。
2. **池空分流**：池空时先看有没有失败条目——
   - 有失败 → **不触发补货**，只发一张提示卡：「有 3 条合成失败，先重试或换音色」；
   - 真没内容 → 才允许 agent 写稿。
3. **熔断与预算**：同一条失败 2 次即停止自动重试，只留手动按钮；同一场次「自动补货」5 分钟内最多 2 次，到顶即停并明确告知。

目标：让"失败 → 重新生成 → 再失败"在第二圈就断掉。

## 八、语言与音色：能力矩阵 + 软校验

音色元数据补齐：`支持语言[]`、`接入`、`模型`、`是否克隆`、`风格指令`、`是否多语模型`。

| 情况 | 表现 |
|---|---|
| 语言 ∈ 音色声明支持 | 绿色，直接开播 |
| 语言 ∉ 声明支持，但模型是多语模型 | **黄色警告** + 「仍可尝试，建议先试听一条」——允许继续（甲方说的"太死板"就是这里） |
| 模型 id 不存在 / 接入已删 | 红色阻断，给替代项 |

**模型清单核对（待办）**：当前百炼侧出现 `qwen-audio-3.0-tts-flash`、`qwen3-tts-flash`、`qwen-audio-3.1-tts-flash`、`cosyvoice-v2`、`cosyvoice-v3-plus`、`cosyvoice-v3-flash`、`cosyvoice-v3.5-plus`、`cosyvoice-v3.5-flash`；火山侧 `seed-tts-2.0`、`seed-icl-2.0`、`seed-icl-1.0`、`seed-tts-1.0`。
需逐条对官方文档确认：**模型 id 是否存在、支持哪些语种、是否支持风格指令**；结论做成一份**配置化清单**（数据文件，不是散在代码里的常量），不存在的删掉、存疑的标「实验性」。

## 九、双语话术

- 话术条目新增两个字段：`textTarget`（播出语言，喂 TTS）与 `textZh`（中文对照，不发声）。
- 生成时一次产出两份：外语节目**强制**要对照；中文节目对照可空。
- 播出区：目标语大字 + 中文小字（可折叠）；底稿列表可展开看对照，点播按钮旁边就看得到这句中文说的是什么。
- 导出可选：只导目标语 / 目标语 + 对照双栏。

## 十、数据模型变更与迁移

| 变更 | 处理 |
|---|---|
| `personas.voiceId` 去掉 | 旧值迁成"该主播的默认音色建议"，开播配置预填用，不再是必填校验 |
| `programs.personaIds` 降级 | 变成"建议主播"（可选、不参与预检阻断）；真正用谁由本场配置决定 |
| `programs.language` | 降级为"写稿语言"（只影响离线写稿；播出语言在开播配置里选） |
| 新增 `session_configs` | programId / leadPersonaId / voiceId / language / broadcastMode / 互动开关 / 音频策略 / createdAt，写进对应场次记录 |
| 话术条目 | + `textZh`、+ `failReason`、+ `retryCount` |
| 历史场次 | 不动；按当时快照渲染 |

迁移走现有 umzug 迁移器：新增 `0016-decouple-assets.ts`，并在 `scripts/db-migrate-check.mjs` 补一条从旧结构抬升的用例。

## 十一、Agent 职责收窄

- **继续做**：写稿、改稿、回评论、回答导演提问、按指令插播。
- **不再做**：合成失败自愈、状态修复、自动重试、看到池空就无脑补货。
- 失败以卡片交给导演：「第 12 条合成失败：音色不支持泰语（重试 2 次已熔断）→ 换音色 / 跳过 / 改写」，由人或导演显式决策。
- 写稿时从**当前场次配置**取语言与主播，不再从节目卡里读卡司。

## 十二、分期

| 期 | 内容 | 预估 |
|---|---|---|
| **P0 止血** | 失败条目可见 + 池空分流 + 熔断 + 切节目列全量 + 已播置灰 + 从此处播/仅播此条 | 1–2 天 |
| **P1 开播配置 + 工作台** | 直播配置弹窗（语言/主播/音色/播出方式/音频策略）、资产解绑、节目只存底稿、顶栏本场快照 | 3–5 天 |
| **P2 双语** | 双字段生成、对照显示、导出对照 | 3–5 天 |
| **P3 能力矩阵** | 音色语言元数据、软校验、模型清单核对与配置化 | 2–3 天 |

P0 先发一版给甲方验证「不再死循环、能看见状态」；P1 再动信息架构，避免一次性大改带来新的混乱。

## 十三、逐条验收

| 甲方原话 | 方案落点 | 验收方式 |
|---|---|---|
| 切节目立马显示全部话术稿，已播灰色 | 工作台左栏全量列表 + 状态徽标 | 切 3 个节目，条数与节目底稿数一致 |
| 每条支持从此处播 / 仅播此条 | 条目 hover 动作 | 播到第 5 条时点第 2 条「从此处播」，检查顺序 |
| 失败→以为没稿→重生成→死循环 | 失败可见 + 池空分流 + 熔断 | 选不支持的语言开播，观察 3 分钟内只失败一次、弹提示且不再生成 |
| 开播才配主播/音色/语言 | 开播配置弹窗（每次必经） | 新建主播不需要选音色；新建节目不需要选主播；开播一次选完 |
| 音色不支持泰语也能播，太死板 | 能力矩阵 + 黄色软校验 | 泰语 + 中文音色 → 黄色警告且可继续 |
| 有些模型根本不存在 | 对官方文档核对 + 配置化清单 | 逐个模型能说出出处 |
| 跨境看不懂 | 双字段 + 对照显示 | 泰语节目播出时中文小字同步可见 |
| 点击播放可选清空重合成或复用音频 | 开播配置⑤音频策略 | 两条路径各开播一次，核对就绪条数与耗时提示 |

## 十四、假设与待确认

1. **配置弹窗预填**：每次必弹，但字段预填上次的值（不写回资产）。若甲方要求"每次全空白"，改成不预填即可。
2. **离线写稿语言**：不开播时（节目卡上"AI 写稿"）用节目的「写稿语言」；没设置则弹一个小选择，默认中文。
3. **播出方式**（一遍/循环/停止）从节目属性移到本场配置；节目上的旧值作为默认勾选。
4. **历史场次**保留当时配置快照，不随资产变更而变。

## 十五、模型修订 v2：剧本 / 本场 / 话术（本节覆盖前文冲突处）

> 前文（第三～十节）把「节目」当作底稿容器。经甲方补充（节目只是可复用资产、底稿按主播生成、话术在工作台产生）后，模型调整如下；与本节冲突的以本节为准。

### 15.1 三层职责

| 层 | 存什么 | 不存什么 |
|---|---|---|
| **资产（可复用）** | 剧本（场次序列：目标/时长/要点/CTA）、素材条目、主播卡（人设）、音色（能力） | 不存台词、不存"谁配谁"、不存播出参数 |
| **本场（一次开播）** | 引用的剧本 + 主播 + 音色 + 语言 + 三个播出开关 + 本场话术 | 不写回资产 |
| **运行时** | 话术队列/状态、水位、实时车道、失败与重试 | 不改剧本结构 |

**话术（底稿）是本场产物**：按 `剧本场次 × 素材 × 主播 × 语言 × 风格` 生成，换主播/换语言即失效并提示重写。想复用只能点「另存为话术模板」，模板记录生成上下文，换人导入时标黄提示。

### 15.2 导入剧本 = 引用 + 本场覆盖

- 导入只建立引用：工作台拿到场次序列与每场的生成目标，剧本数据不动。
- 工作台里改台词/删段/调语气，写入**本场覆盖层**（`session_items`），不写回剧本。
- 需要沉淀时，显式「把这一场存回剧本要点」——存结构性的收获（有效钩子、痛点顺序），不存整段台词。

### 15.3 三个正交开关（替代"模式"枚举）

| 开关 | 取值 |
|---|---|
| 内容来源 | 本场话术（有限） / 边播边无限生成 |
| 合成时机 | 预合成 / 异步边播边合 / **实时流式** |
| 收尾方式 | 一遍播完停 / 循环返场 / 一直播下去 |

界面只露 4 个预设，高级里才展开三个开关：

| 预设 | 组合 |
|---|---|
| 有声书 / 播客 | 本场话术 + 预合成 + 播完停 |
| 带货 | 本场话术 + 异步边播边合 + 循环 |
| 纯互动 / 闲聊 | 无限生成 + 实时流式 + 一直播 |
| 宣讲 / 发布 | 本场话术 + 预合成 + 循环 |

### 15.4 合成车道（实时档的单列处理）

```
车道 A · 主内容      预合成 / 异步边播边合（按本场配置）
车道 B · 互动回复    固定实时流式，不占水位、不排预合成队列
车道 C · 突发/插播   实时流式，最高优先级
```

互动进来 → 主话术 duck 淡出 → 实时回复 → 恢复。播放条标出每条走哪档，实时档显示首字延迟。

### 15.5 数据模型草案

```
scripts(剧本)       id, name, scenes[{id,title,goal,minutes,keyPoints,cta}]
materials(素材)      不动
personas(主播)       去掉 voiceId
voices(音色)         + 支持语言[]、模型、接入、是否流式
sessions(本场)       scriptId, personaId, voiceId, language, preset,
                     genMode, synthMode(pre|async|realtime), endMode
session_items(话术)  sessionId, sceneId, order, textTarget, textZh, status,
                     failReason, retryCount, audioRef, source(script|agent|manual)
templates(话术模板)  sessionId 快照 + 生成上下文
```

`programs` 迁成 `scripts`（保留场次与素材范围）；卡司丢弃；`programs.language` 降级为写稿默认。

### 15.6 分期（按 v2 修订）

| 期 | 内容 |
|---|---|
| P0（1–2 天） | 失败可见 + 池空分流 + 熔断 + 话术全量列表（先止血） |
| P1（4–6 天） | 本场会话模型 + 导入剧本（引用 + 覆盖层）+ 话术编辑与点播 |
| P2（3–4 天） | 三开关 + 4 预设 + 水位 + 无限生成 |
| P3（3–4 天） | **实时流式车道**（分句合成、打断、duck、降级） |
| P4（3–5 天） | 双语对照、音色语言矩阵、模型清单核对（含流式能力） |
