# 10 · 节目化改造最终方案

> 状态：**方案定稿，尚未实施**。
>
> 原则：复用现有剧本、文稿、话术池、主播 Agent、TTS 抽象、播放引擎和播控能力，但对“场次”领域执行一次性破坏性重构；不保留 `LivePlan`、`live_plans`、`plan*` API 或兼容别名，也不引入播放记录、独立生产工作区、任务中心、交付物中心等非必要概念。
>
> 前置：节目与主播已解耦。节目负责内容和规则，当前主播 Agent 可随时接手。项目仍处于开发阶段，数据库和类型直接迁移到最终结构，不维护新旧双轨。

---

## 1. 产品目标

将现有 AI 直播系统升级为**平台无关的 AI 声音节目工作台**。

一个节目可以：

- 由 Agent 生成、续写和修改文稿；
- 即兴播出、边播边合成或全部预制后播放；
- 接收直播间评论、礼物、关注和业务事件；
- 在本机播放，也可以进入现有 RTMP 音频管线；
- 导出为音频文件，上传到任意内容平台；
- 用于口播节目（带货、宣讲、FM、文章朗读、陪聊）、播客、有声书和广播剧。

用户只需要理解：

```text
这是什么内容？
怎么播？
哪些事件需要通知主播？
播放还是导出？
```

## 2. 核心边界

### 2.1 节目决定什么

- 内容类型；
- 播出方式；
- 剧本、文章、章节和知识范围；
- 哪些事件触发器在本节目启用；
- 播完停止还是循环；
- 预制节目使用哪个 TTS 模型；
- 当前文稿和已生成音频。

### 2.2 主播 Agent 决定什么

- 是否回应直播间动态；
- 回应哪一条；
- 逐条回答还是合并回答；
- 立即插播还是等待当前内容结束；
- 使用文字回复还是语音回复；
- 如何表达、使用什么人格、模型和音色；
- 是否忽略无价值、重复或恶意事件。

### 2.3 播放引擎决定什么

- 当前播放项；
- 顺序、暂停、跳过和循环；
- 音频衔接；
- 插播优先级；
- 将音频送入主进程 AudioPipeline。

### 2.4 全局输出决定什么

- 系统扬声器；
- 由直播伴侣采集系统声音；
- 已开启的 RTMP 混音输出。

节目不保存“抖音、快手、B 站”等平台字段。对节目而言，输出始终只是音频。

## 3. 概念升级

| 当前名称 | 新名称 | 说明 |
|---|---|---|
| 场次 | 节目 | 一份可编辑、可播放、可导出的声音内容 |
| 直播台 | 播控台 | 播放任何类型的节目，不限定实时直播 |
| 底稿/话术库 | 文稿 | 可以是段落、场景、章节或对话轮次 |
| 话术池 | 播出队列 | 实际等待播放的内容与音频 |
| 直播模式 | 删除 | 由内容类型、播出方式、事件规则分别表达 |
| 主播自动触发器 | 删除 | 触发器启用状态归节目 |
| 启动/结束场次 | 播放/结束节目 | 与平台无关 |

本轮直接完成全链路命名重构：`LivePlan → Program`、`live_plans → programs`、`planId/plan_id → programId/program_id`、`activePlanId → activeProgramId`、`plan:* → program:*`。不提供 deprecated 字段、类型别名、旧 IPC 通道、旧表视图或读写回退。

## 4. 节目配置

节目配置只保留四组。

### 4.1 基本信息

```text
节目名称
内容类型
主题与节目说明
剧本 / 文章 / 章节
知识库范围
```

#### 内容类型

```ts
type ContentType =
  | 'spoken'     // 口播节目：带货、宣讲、FM、文章朗读、陪聊
  | 'podcast'    // 播客
  | 'audiobook'  // 有声书
  | 'drama'      // 广播剧
```

内容类型只影响：

- Agent System Prompt；
- 写稿任务书；
- 文稿结构和界面文案；
- 默认播出方式；
- 主播表达规范。

内容类型不限制播放、推流或导出。有声书、播客和广播剧均可在直播软件中播放；口播节目也可以提前全部合成后导出。

#### 同一底层结构的 UI 文案

底层继续复用 `Script / Scene`：

| 内容类型 | Script 显示名 | Scene 显示名 |
|---|---|---|
| 口播节目 | 节目脚本 | 场景 |
| 播客 | 本期大纲 | 环节 |
| 有声书 | 书稿 | 章节 |
| 广播剧 | 剧本 | 场/幕 |

### 4.2 播出方式

```ts
type BroadcastMode =
  | 'improvised' // 即兴播出
  | 'rolling'    // 滚动播出
  | 'prepared'   // 预制播出
```

#### 即兴播出

> 无固定底稿，由主播 Agent 根据导演指令和直播间动态现场说。

适用：

- 交互直播；
- 陪聊和问答；
- 临场主持。

运行规则：

- 不要求底稿；
- Agent `say` 后实时 TTS；
- 无评论和导演指令时可以不说；
- Agent 自行决定是否延续话题；
- 播出队列只保存即将说出的内容。

#### 滚动播出

> 已有底稿，一边播放前面的内容，一边提前合成后面的内容。

适用：

- 带货直播；
- 产品宣讲；
- 长时间循环节目；
- 需要随时改稿或插播的节目。

运行规则：

- 开始时只要求前几段音频就绪；
- 后台维持固定合成窗口，第一版默认 5 段，不暴露给普通用户；
- Agent 可以修改未播放内容；
- 直播间回复可以插播；
- 播完后停止或循环。

#### 预制播出

> 先将节目音频全部合成完成，再播放或导出。

适用：

- 有声书；
- 播客；
- 广播剧；
- FM 风格节目；
- 文章朗读。

运行规则：

- 文稿确认后批量合成；
- 必需音频全部就绪后才能正式播放；
- 可以直接导出；
- 支持导入外部音频；
- 不启用低水位补货和现场续写。

### 4.3 事件规则

节目主表单只显示：

```text
事件规则    已开启 5 项  >
```

点击进入栏内配置页，只选择是否启用：

```text
直播间事件
[x] 欢迎观众进场
[x] 感谢关注
[x] 感谢礼物
[x] 将评论提供给主播
[x] 将提问提供给主播

节目状态
[x] 播出队列为空
[x] 长时间没有新互动
[x] 章节播放完成
[ ] 节目即将结束

业务事件
[x] 商品价格变化
[ ] 商品库存变化
```

普通用户不配置评论批处理秒数、触发器冷却时间或 Prompt 模板。高级参数保留在全局触发器库。

### 4.4 播完以后

```ts
type FinishMode = 'stop' | 'loop'
```

只显示：

```text
播完停止
循环播放
```

即兴播出不显示该项；滚动播出和预制播出显示。

## 5. 事件与互动

### 5.1 主播卡不再配置触发器

主播卡只保留：

```text
姓名
人格
背景
口癖
禁区
语言模型
音色
多角色能力
```

移除：

```text
自动触发器
欢迎规则
冷场规则
互动模式
节目类型
```

同一个主播可以主持不同节目；节目切换不会迫使用户创建多个主播版本。

### 5.2 全局触发器库 + 节目启用项

全局触发器库继续复用现有 `triggers` 表和 `TriggerRuntime`，负责定义：

- 事件条件；
- 默认任务模板；
- 冷却和防刷；
- 事件优先级。

节目只保存：

```ts
enabledTriggerIds: string[]
```

节目不复制触发器定义。

### 5.3 直播间动态收件箱

评论、礼物、关注和进场事件先进入直播间动态收件箱，不直接产生固定回复：

```text
评论 / 礼物 / 关注 / 进场
            ↓
      直播间动态收件箱
            ↓
  有新动态时合并唤醒 Agent
            ↓
Agent 读取当前积压的全部新动态
            ↓
自主决定逐条、合并、延迟或忽略
```

系统只负责收集和防止并发轰炸，Agent 决定回应语义。

如果没有新动态：

- 不唤醒 Agent；
- 不创建无意义的 LLM 请求；
- 有底稿的节目继续播放；
- 即兴节目可以自然停顿。

### 5.4 触发器不直接生成固定对外话术

内容类触发器向 Agent 发送事件任务，例如：

```text
系统：用户“小明”送出了礼物。
```

Agent 决定立即感谢、稍后感谢或忽略。

安全类和纯控制类触发器可以保留确定性操作，但不能绕过 Agent 擅自生成对外内容。

## 6. TTS 模型能力

### 6.1 特殊能力仍属于 TTS 模型

火山 PodcastAPI 在产品层是一个特殊 TTS 模型，不新增“Podcast 后端”概念。

```ts
type TtsModelKind =
  | 'standard'  // 普通单人 TTS
  | 'longform'  // 原生长文合成
  | 'podcast'   // 双人播客专用模型

interface TtsModelCapabilities {
  kind: TtsModelKind
  input: 'text' | 'longText' | 'dialogueTurns'
  output: 'file' | 'stream'
  minSpeakers: number
  maxSpeakers: number
  supportsCloneVoice: boolean
  supportsResume: boolean
  supportsTimestamps: boolean
  maxTextChars?: number
  maxCharsPerTurn?: number
}
```

火山模型示例：

```ts
{
  id: 'volc-podcast-v3',
  label: 'Podcast 双人播客',
  capabilities: {
    kind: 'podcast',
    input: 'dialogueTurns',
    output: 'stream',
    minSpeakers: 2,
    maxSpeakers: 2,
    supportsCloneVoice: true,
    supportsResume: true,
    supportsTimestamps: true,
    maxTextChars: 10000,
    maxCharsPerTurn: 300
  }
}
```

### 6.2 大脑、默认声音与节目合成的归属

三类配置不能混为一体：

| 配置 | 归属 | 说明 |
|---|---|---|
| LLM 大脑模型 | 主播 | 决定 Agent 如何思考、写稿和回应 |
| 默认音色 | 主播 | 是主播身份的一部分，即兴和滚动内容默认使用 |
| TTS 接入与模型目录 | 全局语音服务 | 系统能力，不属于某个主播或节目 |
| 预制节目的合成模型 | 节目 | 决定节目使用普通、长文或 Podcast 合成 |
| 预制节目的声音安排 | 节目 | 旁白、双主持和多角色音色映射 |
| 已生成音频 | 节目 | 是节目资产，切换当前主播不自动改变 |

原则：**主播带着大脑和默认声音；节目决定预制内容用什么合成能力、由哪些声音出演。**

### 6.3 节目声音模式

```ts
type ProgramAudioMode =
  | 'follow-presenter' // 跟随当前主播
  | 'custom'           // 自定义节目声音

interface ProgramAudioConfig {
  mode: ProgramAudioMode

  // 预制或特殊模型；普通即兴/滚动节目可为空，走音色路由
  ttsConnectionId?: string
  ttsModelId?: string

  cast?: Array<{
    roleId: string
    roleName: string
    voiceId: string
  }>
}
```

#### 跟随当前主播

适合单人即兴、滚动直播、单口节目和简单文章朗读：

```text
声音安排
● 使用当前主播声音
○ 自定义节目声音
```

即兴与滚动内容实时使用当前主播默认音色；预制节目开始“生成节目音频”时，将当前主播的音色与模型路由冻结成节目本次声音快照，之后切换主播不会改变已生成音频。

#### 自定义节目声音

适合双人播客、有声书专用旁白、广播剧和不使用当前主播音色的内容：

```text
旁白 / 主持人 / 角色 → 音色
合成模型 → TTS 模型
```

节目不保存 `wholeBackend`、火山 API 开关或 Podcast 后端字段，只保存统一 TTS 模型引用和角色音色映射。界面根据模型 capability 自动变化。

#### 普通 TTS 模型

显示：

```text
声音来源：跟随当前主播 / 自定义
旁白或主音色
逐段或整章（仅模型支持项）
语速、音调、演绎指令
```

普通实时场景选择音色后可沿现有 `接入::模型::音色` 路由自动确定接入和模型，无需重复配置。

#### Podcast 模型

显示：

```text
合成模型：Podcast 双人播客
主持人 A 音色
主持人 B 音色
开场音乐
结尾音乐
语速
```

隐藏逐段、单人音色和实时插播等不适用字段。

### 6.4 模型与播出方式的能力校验

| 播出方式 | 模型要求 |
|---|---|
| 即兴播出 | `kind=standard` 且支持流式输出 |
| 滚动播出 | `kind=standard`，按段生成 |
| 预制播出 | 普通、长文或 Podcast 模型均可，按内容结构选择 |

双人播客要求：

```text
contentType = podcast
broadcastMode = prepared
model.kind = podcast
model.maxSpeakers >= 2
```

### 6.5 统一合成请求

```ts
type TtsSynthesisRequest =
  | {
      type: 'text'
      text: string
      voiceId: string
      instruction?: string
      rate?: number
      pitch?: number
    }
  | {
      type: 'podcast'
      turns: PodcastTurn[]
      speakers: [string, string]
      useHeadMusic: boolean
      useTailMusic: boolean
      speechRate?: number
    }

interface PodcastTurn {
  speaker: string
  text: string
}
```

普通 HTTP/SSE、原生长文、火山 WebSocket v3 协议由各模型适配器实现，上层节目只调用统一 TTS 服务。

### 6.6 Agent 与 PodcastAPI

Agent 生成结构化双人轮次稿：

```ts
[
  { speaker: 'host-a', text: '今天我们聊聊 AI 语音直播。' },
  { speaker: 'host-b', text: '最近实时互动确实很热。' }
]
```

角色音色映射后转换为火山 `action=3` 的 `nlp_texts`。内容生成权始终在本地主播 Agent，火山模型只负责专业双人音频合成。

WebSocket 鉴权、二进制帧、360/361/362/363/154/152 事件、断点续传和错误码全部封装在火山 Podcast 模型适配器内部。

## 7. 合成方式

合成方式不在主节目配置中全部展开，而是由播出方式和所选 TTS 模型决定。

### 7.1 即兴播出

自动使用实时流式合成，不显示额外选项。

### 7.2 滚动播出

自动使用逐段合成和现有合成窗口。第一版固定提前准备 5 段。

如果模型支持前文上下文，可以使用前一段尾句改善连贯性；不支持则自动降级。能力必须由模型 manifest 明确声明，不能假设所有 TTS 都支持。

### 7.3 预制播出

根据模型能力显示：

- 普通逐段预制；
- 原生长文合成；
- Podcast 双人合成。

分段生成后拼成完整文件只能称为“分段合成并拼接”，不能承诺获得原生长文模型的连续表演效果。

### 7.4 外部音频

预制节目支持为场景/章节挂载外部音频：

- 跳过 TTS 合成；
- 进入试听、播放和导出流程；
- 允许与 AI 合成章节混排。

### 7.5 现有“预合成全部”入口的最终语义

当前实现路径：

```text
预合成全部
→ api.utterance.presynth(programId)
→ UtteranceService.kickSynthesis(programId)
→ synthesizeAll(programId)
```

当前能力是：找到节目文稿中所有 `pending / failed` 条目，使用当前生效音色逐条串行调用普通 TTS，遵守服务商间隔与退避重试，最后将每条文稿写为 `ready / failed` 并保存 `audioPath / synthVoice`。

节目化改造后继续复用这个入口，但提升为节目音频的统一生产入口：

| 播出方式 | 按钮名称 | 行为 | 正式播放门禁 |
|---|---|---|---|
| 即兴 | 不显示 | 内容说出时实时合成 | 不需要预制音频 |
| 滚动 | `提前合成全部` | 尽可能把全部文稿逐段提前合成；不点也可边播边合成 | 前若干段就绪即可 |
| 预制 | `生成节目音频` | 根据所选 TTS 模型能力生产全部节目音频 | 选择范围全部就绪且不过期 |

因此，“生成节目音频”不是新建第二套页面或第二套服务，而是将现有预合成能力扩展为 capability 驱动的统一入口。

### 7.6 预制节目合成路线

点击“生成节目音频”后：

```text
Agent 完成文稿
→ 用户或 Agent 审核修改
→ 确认文稿
→ 生成合成计划
→ 按 TTS 模型 capability 执行
→ 所有必需音频 ready 且与当前文稿一致
→ 节目进入可播放 / 可导出
```

全量合成会产生费用。用户点击按钮可直接确认；Agent 调用工具发起时必须先用 `ask_director` 展示范围、预计时长、模型和音色并获得确认。

合成单元优先采用可独立重试的自然内容单位：

- 有声书：每章一个单元；
- 播客：每期一个单元；
- 广播剧：每场或每集一个单元；
- 单篇文章：全文一个单元；
- 普通滚动文稿：每段一个单元。

“节目全部完成”表示所选范围内所有合成单元完成，不要求整本书必须存为一个巨型音频文件。导出时可以再合并。

模型路线：

| 模型 capability | 输入 | 产物 |
|---|---|---|
| `kind=standard` | 自然段/角色台词 | 分段音频；需要时后处理并拼为章节音频 |
| `kind=longform` | 整章/整期长文本 | 完整章节或整期音频 |
| `kind=podcast` | Agent 生成的双人轮次 | 完整双人播客音频 |
| 外部音频 | 用户导入文件 | 跳过 TTS，直接作为就绪产物 |

### 7.7 合成计划与节目内进度

不建立独立任务中心。节目文稿页面直接展示：

```text
节目音频：5 / 12 章完成

✓ 第一章        28:40
✓ 第二章        31:05
◌ 第三章        合成中 63%
! 第四章        失败：供应商限流
· 第五章        等待中
```

提供：

```text
继续生成节目音频
暂停后续合成
重试失败项
重新合成当前章/段
导入外部音频
试听已完成单元
```

状态直接挂在 Scene/Utterance 的预制音频引用上；应用重启时，完成产物保留，遗留 `synthesizing` 重置为 `pending` 或 `failed`，由用户继续。

### 7.8 预制节目正式播放门禁

预制节目正式“播放”前检查所选范围：

```text
所有必需音频 status = ready
音频文件真实存在
sourceFingerprint 与当前文稿一致
音频没有 stale 标记
```

未通过时不静默跳过：

```text
当前节目还不能完整播放：
已完成 8/12 章 · 失败 1 章 · 待合成 3 章

[继续生成节目音频]
[重试失败项]
[仅播放已完成部分]
```

单章/单段只要已经完成即可试听；试听不等于正式播放整个节目。

### 7.9 预制音频与播出队列

预制音频是节目长期资产，挂在 Scene/Utterance 上，不能只存在易失的 `speech_items` 中。

正式播放时才装入现有引擎：

```text
节目章节/期级音频
→ 按节目顺序生成 speech_items
→ SpeechPool
→ PlaybackLoop
→ AudioPipeline
→ 系统声音 / RTMP
```

一章/一期可以对应一个播出队列条目。播放引擎只关心标题、`audioPath`、顺序、状态和循环，不需要理解有声书或播客语义。

播放与导出复用同一批预制音频：

```text
节目预制音频
├─ 装入播出队列播放
└─ 分章复制或合并后导出
```

导出不会重新调用 TTS，避免播放版本和导出版本不一致。

## 9. 数据结构与破坏性迁移

### 9.1 Program 最终类型

```ts
interface Program {
  id: string
  name: string
  theme: string

  contentType: ContentType
  broadcastMode: BroadcastMode
  finishMode: FinishMode

  allowLiveEvents: boolean
  enabledTriggerIds: string[]
```

### 9.2 全链路命名替换

本轮一次性替换旧命名，不保留类型别名、旧函数转发、旧 IPC 通道或旧数据库列：

| 旧名称 | 最终名称 |
|---|---|
| `LivePlan` / `LivePlanInput` | `Program` / `ProgramInput` |
| `PlanKnowledgeScope` | `ProgramKnowledgeScope` |
| `DEFAULT_LIVE_PLAN_INPUT` | `DEFAULT_PROGRAM_INPUT` |
| `live_plans` | `programs` |
| `plan_id` | `program_id` |
| `planId` | `programId` |
| `activePlanId` | `activeProgramId` |
| `plan_sessions` | `program_sessions` |
| `director_timeline.plan_id` | `director_timeline.program_id` |
| `utterances.plan_id` | `utterances.program_id` |
| `plan:*` IPC | `program:*` IPC |
| preload `api.plan` | `api.program` |
| `ScriptService` 中的 plan 方法 | program 方法 |
| `LaunchService` | `ProgramPlaybackService` |
| `SessionsPage` | `ProgramsPage` |

### 9.3 删除的旧字段和概念

```text

平台选择字段

```

`modes.promptModule` 的节目语义直接改由：

```text
contentType + broadcastMode
```

生成。

`modes.wiring` 直接改由：

```text
allowLiveEvents + enabledTriggerIds
```

决定。

### 9.4 数据库迁移策略

项目处于开发阶段，迁移直接得到最终表结构：

1. 将 `live_plans` 重命名为 `programs`，或在 SQLite 不支持目标变更时事务内建 `programs_new`、复制仍有价值的字段、删除旧表、再重命名；
2. 将所有外键列 `plan_id` 改为 `program_id`；
3. 将 `plan_sessions` 直接迁移为 `program_sessions`；
4. 删除 `mode_id`、旧 `voice_id` 等退役字段；
5. 给 `programs` 增加最终节目字段；
6. 删除 `modes` 表；
7. 迁移完成后通过 `PRAGMA table_info` 和外键检查确认旧表、旧列不存在；
8. 不写读取旧结构的运行时代码，不保留旧 schema 兼容分支。

如果开发数据库中的旧实验数据无法无损映射，可以清空对应实验表重新播种；不得因此污染最终代码结构。

### 9.5 继续复用的现有能力

```text

SpeechPool
SpeechItem
PlaybackLoop

```

### 9.6 预制音频存储

为避免引入复杂任务中心，第一版在现有 Scene/Utterance 结构上记录：

```ts
interface RenderedAudioRef {
  audioPath: string
  durationMs?: number
  status: 'pending' | 'synthesizing' | 'ready' | 'failed' | 'stale'

  // 合成时冻结的完整声音快照；切换当前主播不会改写
  ttsConnectionId: string
  ttsModelId: string
  voiceOrCastFingerprint: string
  sourceFingerprint: string

  external?: boolean
  error?: string
}
```

- 逐段音频继续存 `Utterance.audioPath`；
- 整章/整期音频挂在对应 Scene；
- Podcast 整期可使用一个 Scene；
- 应用重启时 `synthesizing` 重置为 `pending` 或 `failed`，允许用户重试；
- 文稿指纹变化时置为 `stale`；
- 开始预制合成时将节目 `audioConfig` 解析成完整模型/音色快照写进产物，之后切换主播或修改主播默认音色不会偷偷改写已生成音频；
- 选择“跟随当前主播”只用于填充合成快照，不形成节目与主播的永久绑定。

不新增播放记录、Run、Deliverable、任务中心等用户不需要的对象。

## 10. Agent 写稿

Agent 继续通过现有对话区和工具修改文稿。

| 内容类型 | 默认任务书 |
|---|---|
| 口播节目 | 场景化分段话术，可滚动补充 |
| 播客 | 完整一期结构；单口或双人轮次 |
| 有声书 | 按章节写作，保持人物和旁白一致 |
| 广播剧 | 角色台词、旁白和音效提示 |

| 播出方式 | 对 Agent 的约束 |
|---|---|
| 即兴 | 不要求底稿，读取现场动态后自主表达 |
| 滚动 | 优先使用已有文稿，必要时补充或修改未播内容 |
| 预制 | 先完成整份文稿，审核后再开始批量合成 |

System Prompt 由以下内容组合：

```text
主播人格
+ 节目内容类型
+ 播出方式
+ 当前节目/场景/章节
+ 启用事件规则
+ 知识库范围
```

### 10.1 Agent 作为系统控制中枢

Agent 不只负责写稿和直播互动，还通过工具接管软件中所有可由人操作的核心资源。原则是：

> UI 与 Agent 工具调用同一组主进程 Application Service；Agent 不模拟点击、不直接写数据库，也不维护第二套业务逻辑。

覆盖范围：

| 领域 | Agent 能力 |
|---|---|
| 节目 | 查询、新建、修改、删除、设为当前节目、播放、暂停、停止、导出 |
| 剧本/文稿 | 查询、新建、改名、增删改场景/章节、调整顺序、批量写稿、修订文本、触发合成 |
| 主播 | 查询、新建、修改人设、模型、音色和角色，删除主播，切换当前主播 |
| 音色库 | 查询、试听、重命名、导入/登记、发起克隆、查看训练状态、删除音色 |
| 知识库 | 查询、创建、修改、删除条目和文件，调用连接器同步外部资料 |
| 事件规则 | 查询全局触发器，将触发器绑定/解绑到节目，修改高级规则 |
| 模型/TTS 接入 | 查询状态与能力，修改非敏感参数、启用模型、测试连接；密钥由用户在安全输入界面提供 |
| 播出控制 | 查看播出队列，插播、修订、撤销、排序、暂停、继续、跳过、急停 |
| 应用状态 | 查询连接器、RTMP、LLM、TTS、音频设备和错误状态，并给出修复建议 |

### 10.2 工具分层

#### 只读发现工具

```text
list_programs / get_program
list_scripts / get_script
list_personas / get_persona
list_voices / get_voice
list_knowledge / get_knowledge_entry
list_triggers / get_trigger
get_system_status
```

只读工具可直接执行，用于 Agent 理解系统当前状态。

#### 可逆写入工具

```text
save_program
save_script / save_scene / reorder_scenes
save_persona
rename_voice
save_knowledge_entry
set_program_triggers
set_active_program
set_active_persona
revise_queue_item / reorder_queue
```

写入工具必须使用结构化参数、服务层验证、幂等语义和明确返回值。保存后通过统一事件广播刷新 UI 和 Agent 上下文。

#### 破坏性或外部副作用工具

```text
delete_program
delete_script
delete_persona
delete_voice
clear_program_content
start_voice_clone
start_program_playback
start_rtmp

```

此类工具执行前调用 `ask_director` 请求确认，确认卡必须显示：

- 将执行什么；
- 影响哪些资源；
- 是否可恢复；
- 当前是否正在被节目、主播或播出队列引用。

急停是例外：安全优先，可直接执行并立即通知导演。

### 10.3 工具设计规则

1. **单一业务入口**：例如 UI 保存节目与 `save_program` 最终都调用 `ProgramService.save()`。
2. **不暴露数据库结构**：工具参数使用业务对象，不接受 SQL、表名或任意字段写入。
3. **幂等**：相同请求重复执行不会创建重复节目、章节、知识或连接器数据。
4. **引用校验**：删除音色、主播、剧本和节目之前检查所有引用关系。
5. **版本/并发检查**：保存时携带 `updatedAt` 或版本号，避免 Agent 覆盖用户刚刚在 UI 中完成的修改。
6. **敏感数据隔离**：Agent 只能知道“密钥已配置/未配置”，不能读取或回显明文密钥。
7. **能力驱动**：选择 TTS 模型、音色和多角色时依据 capability 校验，不能写入模型不支持的组合。
8. **可观察**：每次工具调用进入现有 Agent 时间线，显示动作、目标、结果和错误，但播放控制等高频动作可以折叠避免刷屏。
9. **运行态保护**：修改当前正在使用的人设、模型、音色或节目结构时，返回“立即应用/下次生效/先停止播出”的明确结果，不静默改变运行中的上下文。
10. **失败可恢复**：错误结果包含原因和建议操作，Agent 可以修正参数后重试。

### 10.4 Agent 自我修改边界

Agent 可以修改自己的主播卡，但遵守以下规则：

- 修改口癖、背景等人格文本后，当前会话提示需要“立即应用”；
- 修改模型连接或模型后必须重启 Agent 会话；
- 修改音色后只影响新生成内容，未播旧音色条目按现有 reVoice 规则重合成；
- 删除当前主播、删除当前节目、清空当前节目内容必须人工确认；
- Agent 不能读取 API Key，也不能绕过音色授权或克隆确认。

### 10.5 与节目化重构同步完成

Program 破坏性重构时，同时将现有节目、剧本、主播、音色、知识和触发器服务整理为可供 UI 与工具共享的 Application Service。不得先在工具层复制一套 CRUD，再等待后续合并。

## 13. 实施路线

### P1 · Program 破坏性重构与节目配置

- 一次性执行 `LivePlan → Program`、数据库表/外键、IPC、preload API、服务方法、页面组件和状态字段的全链路改名；
- 删除全部旧 `plan*` 类型、通道、函数和兼容读取；
- 增加 `contentType / broadcastMode / finishMode`；
- 增加 `allowLiveEvents / enabledTriggerIds / audioConfig`；
- 明确主播保留 LLM 与默认音色，预制节目保存合成模型和角色音色安排；
- 触发器从主播卡移到节目；
- 删除 `modes` 表、类型、服务和 UI；
- 更新节目库和节目配置 UI；
- 用全仓检索与数据库 schema 检查确认不存在旧 `LivePlan/live_plans/planId/activePlanId/plan:*` 业务符号。

### P2 · Agent 系统控制工具

- 将节目、剧本/文稿、主播、音色、知识、触发器、连接配置和播出控制整理为 UI/Agent 共用的 Application Service；
- 补齐只读发现、可逆写入、破坏性操作三层工具；
- 接入引用校验、版本冲突、敏感数据隔离和 `ask_director` 确认；
- 通过工具调用时间线和 UI 事件广播验证 Agent 修改后系统状态即时一致。

### P3 · Agent 事件收件箱

- 评论、礼物、关注和进场进入动态收件箱；
- 同一短时间窗口的事件合并唤醒 Agent；
- Agent 自主读取、忽略、合并、延迟和回应；
- 内容类触发器只通知 Agent，不直接输出固定话术。

### P4 · 三种播出方式

- 即兴播出复用实时 TTS；
- 滚动播出复用现有合成窗口和播出队列，“预合成全部”改为“提前合成全部”；
- 将现有 `UtteranceService.kickSynthesis/synthesizeAll` 扩展为 capability 驱动的“生成节目音频”入口；
- 预制播出增加文稿确认、合成计划、节目内进度、全部完成门禁和外部音频导入；
- 预制产物持久化在 Scene/Utterance，正式播放时才装入 SpeechPool；
- 补充普通、长文、Podcast 模型能力校验。

### P5 · 播控台适配

- 根据 `broadcastMode` 自动适配中间区域；
- 即兴模式隐藏无意义的空底稿；
- 滚动模式保留可操作队列；
- 预制模式增加长音频进度、seek 和章节列表；
- 统一播放、暂停、导出和急停入口。

### P6 · 特殊 TTS 模型与导出

- 扩展 TTS Model Capability；
- 接入原生长文模型；
- 将火山 PodcastAPI 注册为 `kind=podcast` 的特殊模型；
- 实现节目内分章/合并导出。

## 14. 验收标准

### 破坏性重构完整性

- TypeScript、IPC、preload、主进程、渲染层和数据库 schema 均只使用 Program 命名；
- 全仓业务代码中不存在 `LivePlan`、`live_plans`、`planId`、`activePlanId`、`plan_id`、`plan:*` 或 `api.plan`；
- 数据库中不存在 `live_plans`、`plan_sessions`、`mode_id` 和 `modes`；
- 不存在 deprecated 类型、别名、兼容适配器或旧结构回退读取；
- 标准 typecheck、生产构建和临时 profile 数据库迁移验证全部通过。

### 节目配置

- 创建节目最多需要理解“内容类型、播出方式、事件规则、播完策略”；
- 普通用户看不到协议和后端工程术语；
- 不适用的 TTS 配置不会显示；
- 主播卡中不再出现触发器；
- 主播卡继续拥有 LLM 和默认音色，但不拥有预制节目的合成模型与角色选角；
- 即兴/滚动节目默认跟随当前主播，无需重复选择普通 TTS 路由；
- 预制节目可选择“跟随当前主播”或“自定义节目声音”；
- 开始预制合成后，模型与音色作为产物快照冻结，切换当前主播不改写已有音频。

### Agent 系统控制

- Agent 可以通过工具查询、新建、修改和删除节目、剧本/文稿、主播、音色和知识条目；
- Agent 可以绑定节目触发器、切换主播、控制播出队列并查询全局状态；
- UI 和 Agent 工具调用同一 Application Service，结果与校验一致；
- 删除、清空、克隆、导出和外部启动等高风险动作有明确确认；
- Agent 无法读取明文密钥、绕过音色授权或直接操作数据库；
- Agent 写入与用户同时编辑发生冲突时，不静默覆盖用户修改。

### Agent 互动

- 没有新动态时不会触发无意义 LLM 请求；
- 多条相似评论可由 Agent 合并回答；
- Agent 可以忽略无价值事件；
- 换主播不改变节目启用的事件规则。

### 播出

- 即兴节目无需底稿即可播放；
- 滚动节目可以边播边合成并插播，“提前合成全部”不是正式播放门禁；
- 预制节目通过现有预合成入口升级后的“生成节目音频”生产全部音频；
- 预制节目正式播放前检查所选范围全部 `ready`、文件存在且文稿指纹一致；
- 已完成单元可以单独试听，完整播放缺项时不静默跳过；
- 预制音频持久化在节目内容单元上，重启不会随播出队列清理；
- 同一批预制音频同时用于播放和导出，导出不会重复调用 TTS；
- 节目播放能同时进入系统声音和已启用的 RTMP 管线；
- 节目不感知具体平台。

### TTS

- 普通、长文和 Podcast 模型统一出现在 TTS 模型体系中；
- 选择模型后 UI 按 capability 自动变化；
- 火山 PodcastAPI 的协议细节完全封装在模型适配器中；
- Agent 负责生成双人轮次稿，Podcast 模型只负责合成。

### UI

- 播控台不出现人工“三模式界面切换”；
- 节目设置主页面没有大量触发器按钮；
- 事件规则使用独立栏内页；
- 1366×768 下关键操作不被裁切；
- 所有关键状态同时使用文字和图标表达。

## 15. 边界情况与降级规则

本节是实施时必须满足的行为契约，不属于后续优化项。

### 15.1 内容类型组合

`spoken` 表示口播内容，不表示是否直播。常见组合：

| 场景 | 内容类型 | 播出方式 | 播完策略 |
|---|---|---|---|
| 交互直播 | 口播 | 即兴 | 不适用 |
| 带货直播 | 口播 | 滚动 | 停止或循环 |
| 产品宣讲 | 口播 | 滚动或预制 | 停止 |
| FM 励志/陪伴 | 口播 | 预制 | 循环 |
| 文章朗读 | 口播 | 预制 | 停止或循环 |
| 双人播客 | 播客 | 预制 | 停止或循环 |
| 有声书 | 有声书 | 预制 | 停止或循环 |
| 广播剧 | 广播剧 | 预制 | 停止或循环 |

### 15.2 即兴节目无互动

- 没有评论、导演指令或启用的主动触发器时，不唤醒 Agent；
- 允许自然安静，不默认定时自言自语；
- 只有节目启用“长时间无互动”或“主动找话题”后，系统才向 Agent 发送提醒；
- 提醒仍由 Agent 决定是否行动，不直接产生固定话术。

### 15.3 高频与低频直播间动态

事件进入收件箱后依次执行：

1. 连接器事件 ID 去重；
2. 纯表情、垃圾和重复刷屏基础过滤；
3. 相同问题归组并计数；
4. 价格、售后、明确提问等高优先级识别；
5. 自适应聚合；
6. 单批事件数与字符数上限；
7. 超量事件摘要。

系统必须设置保护参数：

```text
每批最大事件数
每批最大字符数
每分钟最大 Agent 唤醒次数
未处理事件最长保留时间
```

- 低频重要评论以很短延迟唤醒 Agent，不固定等待 20 秒；
- 高频评论扩大聚合窗口，一批只触发一个 Agent 回合；
- 持续高峰传增量摘要，不重复携带完整事件历史；
- 高频互动仍会增加 Token 成本，但不会按评论数量线性创建 LLM 请求；
- 实际回复延迟仍受模型首 Token、TTS 首包、当前音频剩余时间和 Agent 插播决策影响，不承诺固定绝对时延。

事件状态至少区分：

```ts
type LiveEventState = 'new' | 'seen' | 'handled' | 'ignored' | 'expired'
```

连接器重连后的重复事件不会再次回复；过期评论不会在很久以后突然补答。

### 15.4 滚动播出队列见底

处理顺序：

1. 播放所有已就绪内容；
2. 后台继续合成；
3. 低水位或队列空事件通知 Agent；
4. Agent 可以补充短内容，也可以不补；
5. 无可播放内容时等待，允许冷场；
6. 只有整轮播放完成且 `finishMode=loop` 时才循环整轮。

临时没内容不能触发状态机自旋、无条件循环或重复唤醒 Agent。

### 15.5 预制节目部分失败

- 已完成章节随时可以试听；
- 正式连续播放默认检查选择范围是否完整；
- 缺少章节时默认阻断，并提供“只播放已完成部分”；
- 导出默认要求所选范围完整，也可明确选择“仅导出已完成部分”；
- 失败章节显示原因和重试入口，不隐藏在总进度中。

### 15.6 文稿修改与音频过期

音频保存合成时的文本指纹：

```ts
sourceFingerprint: string
```

当前文稿指纹不一致时，音频标记为 `stale`。正式播放和导出前必须提示：

```text
重新合成
继续使用旧音频
取消本次修改
```

不得静默播放与当前文稿不一致的旧音频。

### 15.7 换主播与已有音频

#### 即兴/滚动节目

- 当前播放内容不强行替换；
- 未播的动态内容可按现有 `reVoice` 使用新主播音色重合成；
- 已播内容不处理。

#### 预制节目

切换当前控制 Agent 默认不重新合成已有音频。用户选择：

```text
只让新主播接管对话和互动（默认）
使用新主播音色合成未完成内容
重新合成全部节目音频
```

不得因切换主播自动触发整本有声书或整期播客重合成。

### 15.8 主播模型、音色或 TTS 失效

| 情况 | 行为 |
|---|---|
| 已有可用预制音频 | 照常播放 |
| 需要生成新内容但音色/TTS 不可用 | 该内容合成失败并提示重选 |
| 即兴播出没有可用 TTS | 阻断播放 |
| 滚动播出 TTS 失效 | 存量照播，新增内容无法合成 |
| LLM 不可用 | 已有音频照播，Agent 写稿与互动降级 |

删除音色前显示主播、角色、节目和待播队列引用。删除音色不删除已经生成的音频文件，但后续重合成必须重选音色。

### 15.9 Podcast 模型失败与能力边界

- WebSocket 中断时模型适配器使用 `retry_task_id + last_finished_round_id` 断点续传；
- 内容审核、配额不足或不可重试错误必须显式显示；
- 用户可修改文稿、换 Podcast 模型，或经确认改用普通双角色 TTS；
- 不允许无提示自动降级，因为音质和节奏会变化；
- `maxSpeakers=2` 时禁止用于三人以上内容或多角色广播剧；
- 单轮和总文本超过模型限制时，在请求前给出明确校验，不等服务端报错。

### 15.10 分段合成的质量边界

- 原生长文模型才是真正共享长上下文；
- 分段合成每段仍是独立调用；
- 分段拼接只能改善停顿、淡入淡出和响度一致性；
- “上一段提示”只有模型 capability 明确支持时启用；
- 不承诺普通分段 TTS 达到原生长文的语气连续性。

### 15.11 循环范围

- 单篇文章：循环整篇；
- 播放单章：可临时循环当前章节；
- 播放全书：循环整本；
- 滚动节目：整轮文稿全部播放完成后循环整轮；
- 即兴播出：没有循环概念。

节目设置默认显示“循环整个节目”；“单章循环”属于播放器临时控制，不修改节目默认值。

### 15.12 播放中修改内容

- 正在播放的内容不能删除或替换；
- 用户可以急停；
- 只允许修改后续未播放内容；
- 新内容可以插入下一条；
- 当前内容播完后使用修改后的版本。

### 15.13 播放与 RTMP

- RTMP 未启动不影响本机播放成功；
- 播放中开启 RTMP，从当前时刻开始输出；
- 播放中关闭 RTMP，本机播放继续；
- RTMP 错误只显示全局输出告警，不默认停止节目；
- 直播伴侣采集由外部软件负责，节目不感知平台。

### 15.14 应用重启

- 即兴和实时播出不自动恢复；
- 易失播出队列按现有规则清理；
- 预制节目已生成的 Scene/Utterance 音频必须保留；
- 启动时将遗留的 `synthesizing` 重置为 `pending` 或 `failed`；
- 用户手动继续批量合成，不新增独立任务中心。

### 15.15 Agent 系统控制安全

- 查询工具直接执行；
- 可逆写入使用结构化参数、幂等语义和版本检查；
- 删除、清空、克隆、导出及外部启动等操作需 `ask_director` 确认；
- 急停可立即执行并通知导演；
- 密钥只暴露“已配置/未配置”；
- 当前资源变更返回“立即应用/下次生效/先停止播放”，不静默热改；
- 保存携带 `expectedUpdatedAt` 或版本号，冲突时拒绝覆盖用户刚完成的修改。

### 15.16 删除与引用

| 资源 | 删除规则 |
|---|---|
| 当前正在播放的节目 | 必须先停止；节目文稿和节目级音频一起删除，不删全局资产 |
| 被节目引用的剧本 | 显示引用节目，先解绑后删除 |
| 当前主播 | 先切换其他主播；已预制音频保留 |
| 被引用的音色 | 显示主播、角色、节目和队列引用；已有音频保留，后续合成需重选 |

### 15.17 导出边界

第一版至少处理：

- 输出目录不存在；
- 文件重名；
- 磁盘空间不足；
- 部分章节缺音频；
- 外部音频文件被移动；
- 文件名包含非法字符；
- 合并失败后的临时文件清理；
- 导出过程中源音频被重新合成。

不建立独立导出中心，但导出动作需要进度、取消和明确错误反馈。

### 15.18 第一版明确不承诺

1. 不承诺普通分段 TTS 达到原生长文模型的语气连续性；
2. 不承诺所有平台都有评论连接器；
3. 不承诺高频评论完全不增加 Token 成本；
4. 不承诺低频评论固定在某个绝对时延内回复；
5. 不承诺 Podcast 模型支持两个以上角色；
6. 不做完整 DAW、波形剪辑和多轨混音；
7. 不做永久播放历史系统；
8. 不做独立任务中心；
9. 不做平台账号与节目绑定；
10. 不自动从失败 Podcast 模型无提示降级到普通 TTS。

## 16. 最终产品模型

```text
节目决定：
- 是什么内容
- 即兴 / 滚动 / 预制
- 哪些事件通知主播
- 播完停止还是循环
- 选择哪个 TTS 模型

主播 Agent 决定：
- 是否回应
- 回应什么
- 什么时候回应
- 逐条还是合并
- 怎么说
- 使用自己的模型和音色

播放引擎决定：
- 当前播出队列
- 音频衔接
- 暂停、跳过和循环

全局音频管线决定：
- 系统出声
- 直播伴侣采集
- RTMP 输出

节目提供：
- 播放
- 导出
```

最终原则：**场次升级为节目，触发器归节目，回应决策归 Agent，特殊能力归 TTS 模型，输出保持平台无关。**
