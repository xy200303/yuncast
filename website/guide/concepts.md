# 核心概念

## 项目 = 目录 = 数据库

一个项目就是一个目录：`project.db` 存场次、底稿、对话与播出记录，`assets/` 放项目内附件。没有独立的「剧本库」「知识库」「素材库」——这些概念都并进项目里了。

- 切换项目 = 切换一整套上下文（场次、稿子、对话、音频）
- 备份用「项目 → 导出」：合成音频会一起打进 ZIP 的 `audio/`，换台电脑直接打开；直接拷目录只含稿子与记录
- 应用配置（API Key、音色库、接入）在用户数据目录，不跟项目走

## 场次

每真正播出去一次，就留一条**场次**：这场什么时候开始、播了多少条、评论与事件、观众画像都在里面。改项目不会动到已经播过的场次。

## 本场配置：语言、形态、合成时机、收尾

开播配置里有三组开关，它们决定「怎么写、怎么合、怎么收」：

| 配置 | 选项 | 影响 |
| --- | --- | --- |
| **语言** | 中文 / 英语 / 日语 / … | 写稿用什么语言写；中文对照放译文栏。写稿工具按它校验 |
| **内容形态** | 一个人讲 / 多人聊天 / 照着稿子读 / 分角色表演 | 写稿与播出的表达方式 |
| **合成时机** | 预合成 / 边播边合 / 实时 | 开播前合、边播边合、还是逐句实时合成 |
| **收尾** | 一遍播完 / 循环返场 / 一直播 | 播完之后停、回到第一段、还是接着写新内容 |

> 内容来源不是独立选项：选「实时」就是现场生成，其余都是按本场稿子播。

## 稿子与声音

- **底稿**：一段 30~90 秒的连续讲述，是合成和播放的最小单元；写稿工具一次写 1~4 段
- **本场默认音色**：整场用谁的嗓子；个别段落可以单独覆盖（段落音色优先）
- **克隆音色**：音色库里上传样本复刻；音色绑定它所属的接入与模型，接入删掉就合不出声
- **已合成标记**：卡片上标出哪段已经有音频；改一个字旧音频作废，需要重新合成

## 播放顺序只认稿子

池条目带一个「稿子位置」`queue_seq`，装载时按底稿顺序写死，播放/循环/上一段都不会改它：

- **循环返场**：播完一轮把同一批条目回卷到就绪，从第一段重来（音频复用，不重新合成，也不会复制话术库）
- **一直播**：不回卷，让主播写新桥段继续播，旧段不再重播
- **上一段**：回到同一行并排到队首；已播过的也不会新建一条
- **现场插话**：走「下一条 / 打断」车道优先播完，队列从原位置继续；这类条目没有稿子位置，**不参与循环复播**

## 话术池

所有要出声的内容都进同一个池，按车道排序：**打断 > 下一条 > 常规 > 垫底**。评论回复、急事插播走「下一条」，其余按稿子顺序正常播。

## 事件流

评论、进场、礼物先进事件流，不直接打断主播：同人同内容去重、按观众归组、按批交给主播。要不要接由顶栏「自动响应」决定；关掉时主播看不到任何直播间动态，专心按稿子演。

## 预制门禁

「预合成」的场次在开播前过一道门禁：逐段核对音频是否齐、是否还跟当前文稿对得上。缺项会照实列出来，可以「继续生成」补齐，或「仅播放已完成部分」先播有的。
