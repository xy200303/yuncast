# 抖音直播互动工具合规清单

> 本清单用于开发、联调和提审前自查，不替代抖音开放平台的最终审核结果。以控制台当前展示的能力、协议和审核意见为准。

## 官方形态

本项目采用“仅直播伴侣”的 EXE 互动工具形态：

```text
直播伴侣启动 EXE（PipeSDK 参数）
        ↓
桌面端订阅 OPEN_LIVE_DATA
        ↓
评论预处理 → AI 语音稿 → TTS → 主播声音输出
```

- 产物类型应在提审前确定；官方文档说明审核通过或上线后不能再变更。
- EXE 只从直播伴侣互动工具入口启动，不提供房间号抓取、网页 WebSocket 逆向、Cookie 登录或代理抓包能力。
- 正式数据通道只使用 PipeSDK 的 `OPEN_LIVE_DATA`，不把调试模拟消息当作平台数据。
- 直播画面和最终开播由直播伴侣负责，桌面端只提供助播逻辑、语音和合规的互动素材。

## 能力与权限

- 在开放平台申请与实际功能一致的开放数据能力，最小化申请范围。
- 需要评论时申请“互动数据”以及“直播间评论互动数据”；未申请的能力不得在 UI 中承诺可用。
- 点赞、礼物、关注、粉丝团等能力只有在实际实现并申请对应权限后才能展示。
- 互动工具调试需要开发协作者权限、调试成员权限和绑定的测试抖音号；线上验证使用真实直播间环境。
- 直播伴侣调试版本以官方当前文档要求为准，不再依赖历史 LocalTest 调试包。

## 互动边界

- “自动回复”统一表述为“自动语音助播/语音播报”，表示主播通过声音回答观众。
- 不实现、不宣传向抖音评论区自动发送文字，不模拟主播账号发言。
- 每条 AI 语音稿进入队列后都可以跳过、改稿或紧急停止；默认不应在用户不知情时自动播报。
- 语音稿不得承诺知识库之外的价格、库存、功效、售后、收益或中奖结果。
- 医疗、金融、投资、功效保证、联系方式索取、辱骂和其他高风险内容应拦截或转人工处理。

## 数据与隐私

- PipeSDK 返回的 `sec_open_id` 是加密用户标识，只用于本场去重和业务流程，不向用户展示、不用于跨场追踪。
- 评论内容、昵称和用户标识只保留完成助播和必要复盘所需的最短期限；发布前应补充清理策略。
- 调用外部 LLM/TTS 前在设置页明确提示评论内容会发送到已配置的模型服务，并提供关闭自动助播的开关。
- 不在日志、错误弹窗和导出文件中输出 LLM/TTS 密钥、Access Token 或完整用户标识。

## 抖音云与网络请求

如果改为“抖音 App + 直播伴侣”小程序型互动工具，或使用直播互动工具 JS API 的网络请求能力，按官方要求将后端部署到抖音云生产环境；开发环境不能作为线上流量的后端。当前 EXE + PipeSDK 版本不使用 JS API 网络请求链路。

## 提审前检查

- [ ] 控制台产物类型选择“仅直播伴侣 / EXE”，并完成应用基础信息。
- [ ] 只申请并实际使用已获批的互动数据权限。
- [ ] 使用调试成员和真实直播间完成评论、断线、退出、重连测试。
- [ ] 关闭模拟器后，软件无法在没有直播伴侣参数时伪造平台评论。
- [ ] 界面明确显示“仅语音播报，不发送评论文字”。
- [ ] 默认关闭自动语音助播，人工可跳过、改稿和紧急停止。
- [ ] 价格、商品和售后回复只能来自已配置知识库；不确定时转人工。
- [ ] 审核包、隐私说明、权限说明和实际功能保持一致。
