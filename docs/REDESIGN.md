# YunCast 交互与架构重构 · 最终方案

> 版本：v1.0（定稿）
> 目标：**让完全不懂技术的店家/主播也能上手**——消灭隐式状态、消灭内部术语、agent 全局解耦、系统无 agent 也完整可用。
> 渲染端：React + TSX（`src/renderer/src`）；主进程：`src/main/services`；共享类型：`src/shared/types.ts`。

---

## 1. 设计原则

1. **没有隐式状态**：任何影响行为的状态（谁在播、用谁的声音、走哪条接入、什么策略）都必须在做决策的界面上看得见。
2. **配置即所见**：点"合成"前知道合成的结果是什么；点"开播"前知道这场播的是什么、谁播、什么声音。
3. **导演是唯一 agent，主播只是卡**：所有"想"的事（写稿、回复、调度）归系统唯一的导演；主播是"人设口吻 + 嗓音"的纯配置卡，没有大脑。导演是帮手不是黑盒——人能手动做导演做的所有内容类操作。
4. **系统无导演可用**：节目、底稿、合成、播放、场次、导出全部不依赖导演核心功能。
5. **开播即定格**：一场播出的导演大脑版本/出镜主播/声音/策略在开播时刻冻结成快照，场次完整记录，不留两套口径。
6. **错误必须指路**：任何报错 = "出了什么事 + 去哪修"，禁止技术原文透传到用户界面。

## 2. 核心概念模型

> **核心抽象：「想」的全归导演，「说」的全归主播卡。** 导演是系统唯一内置 agent（有自己的大脑）；主播只是"人设口吻 + 嗓音"的纯数据卡，没有大脑。

| 概念 | 职责 | 关键规则 |
|---|---|---|
| **导演（Director）** | 系统唯一 agent：回复评论、写稿、改稿、插播、调度、建节目、选角……所有"想"的事 | 有自己的大脑（LLM 接入/模型，全局配一次）；身份恒定，**从不开口出声** |
| **主播（Presenter）** | 纯配置卡：名字、人设口吻、口头禅、背景、禁忌、嗓音、角色 | **没有大脑**；是导演的"风格卡 + 嗓子"；可多张并存（播客双主持 = 两张卡） |
| **节目（Program）** | 内容容器 + 播放配置：内容类型、播放策略（即兴/滚动/预制）、互动策略、触发器 | 只是配置模板；从节目产生场次 |
| **底稿（Utterance）** | 节目的话术内容；来源三路：手写 / 导演写 / 直播中改 | `source` 标记来源；人随时可以覆盖导演写的 |
| **场次（Session）** | 节目的一次播出实例 | 开播时刻冻结快照：导演大脑版本 + 出镜主播卡 + 策略全部落场次 |
| **合成（Synthesis）** | 系统任务：底稿 → 音频 | 每条音频的声音在合成时刻冻结；不经过 agent |
| **AgentPanel** | 导演的驻场面板：全局三态停靠，任何页面可唤起 | 只通过工具调用连接系统 |

### 导演怎么"让主播说话"（防精分设计）

台词对导演是**作品不是自我**，双通道永不混：

1. **后台通道**：用户 ↔ 导演对话，导演始终以导演身份回应（"好，我让小陶加一段催单"）。
2. **舞台通道**：主播开口 = 导演调 `say`/`edit_draft`，台词写在**工具参数**里（"以「小陶」的口吻写：人设…口头禅…"），用主播的 voiceId 合成。
3. **Prompt 分层**：system 恒定是导演身份；主播卡以"你手下主播的资料"注入，是任务素材不是身份。多主播 = 卡司表，导演分角色写词、各配各的嗓音。
4. **台词子调用**（防口吻串味的终极手段）：发现导演把后台口气带进台词时，台词生成改为独立子调用——干净 messages（导演提示词 + 主播卡 + 素材），不带与用户的聊天历史。

### 播放策略三分（不变，但 UI 统一）

| 策略 | 底稿 | 合成 | 适用 |
|---|---|---|---|
| `prepared` 全部做好再播 | 整篇/整章 | 开播前全部预制 | 有声书、播客、FM、宣讲 |
| `rolling` 边播边准备 | 一段一段 | 滚动合成（可提前合成） | 直播带货、讲解 |
| `improvised` 现场发挥 | 无底稿 | 直播现场合成 | 纯互动直播 |

### 声音规则（统一为一句话）

> **每条音频的声音在它被合成的那一刻冻结；没提前合成的，直播时按开播定格的出镜主播嗓音现场合成。**

- 开播时刻把"卡司 + 嗓音"定格到场次；直播中换声音 = **纯合成层操作**（`switchPresenter`：换风格卡注入 + 换 voiceId + 池里存货重合成），不换脑、不重启会话，导演会话零感知。
- **声音不在节目里配**：所有合成入口都先弹「合成声音」，在那里选接入/模型/音色（播客还要选两位主持人和配乐），确认后才合成、并把这次的选择冻结进每段产物。节目上老数据里存的 `audioConfig`（含 `voiceId`/`cast`）只作为历史值/导演工具用，界面上不再有「声音安排」这一栏——同一件事有两个配置入口只会互相打架。
- 滚动/即兴节目开播前的"提前合成"同样走合成弹窗，显式选声音。

### 节目卡司（presenterIds）

- 节目上挂 `presenterIds: string[]`——**一口气可以选多张主播卡**（相当于告诉导演"你手下有哪些人设可用"）；播客双主持不再需要 audioConfig.cast 特例，卡司 = 2 就是双主持。
- **空数组 = 导演自选**：导演按节目内容自己挑人设、甚至现场立一张新卡；开播确认页必须显示清楚（"卡司：小陶、老周" 或 "卡司：导演自选（小陶）"），可见性原则不破。
- 合成弹窗默认用节目卡司；多卡司时按角色分派或手动指定用哪张。
- 原 `Persona.roles`（卡内角色）废弃，由卡司（多张卡）统一取代——破坏性更新。
- 主播团页只是卡的管理处（人设 + 嗓音）；节目编辑里加"卡司"多选。**这页没有"启动/停止主播"开关**——会话的启停在播出流程里（开播 / 写稿自动就位），大脑在设置里，人设卡页不该再放一个能起会话的按钮（原来那个「启动主播」是旧模型残留，已删）。

## 3. 系统架构变化

### 3.1 Agent 解耦（核心变更）

**现状**：agent 对话 UI 长在 `LivePage.tsx` 右栏（`DirectorConsole`），生成底稿必须跳页，agent 与播控台强耦合。

**目标架构**：

```
┌────────────────────────────────────────────┐
│ 渲染层（React）                              │
│  ┌──────────────────────────────────────┐  │
│  │ AgentPanel（独立组件，三态停靠）        │  │
│  │  · 浮窗 / 侧边栏 / 最小化球            │  │
│  │  · 会话连续、关窗不杀任务              │  │
│  │  · 上下文芯片感知当前页面              │  │
│  └──────────────┬───────────────────────┘  │
│                 │ IPC（agent.* 通道）        │
├─────────────────┼──────────────────────────┤
│ 主进程                                        │
│  AgentService ──工具调用──> 各系统服务        │
│  （写稿/改稿/查询/播报）  （底稿/合成/播放/    │
│                          场次/知识库）       │
│  系统服务彼此独立，无 agent 照常运转           │
└─────────────────────────────────────────────┘
```

**解耦要点**：

1. `AgentPanel` 抽成独立组件，从 `LivePage.tsx` 剥离；LivePage 右栏 = AgentPanel 的停靠态。**面板里坐的是导演本人**（固定身份），不是"当前主播"。
2. 导演对系统的所有操作**只走工具调用**（已有的 anchorTools / anchorSystemTools 体系），UI 层不私开后门。
3. 系统所有功能（建节目、写底稿、合成、开播、导出）都有纯手动 UI 路径，不经过导演。
4. AgentService 未配置导演大脑（LLM）时：系统全部功能可用，仅 AgentPanel 显示"还没给导演配大脑"的引导态。
5. 主播卡不再含大脑：原 `Persona.modelConnectionId/model` 迁移为全局 `directorConfig`（取现有主播中最常用的那套作为导演大脑默认值，破坏性迁移）。

### 3.2 会话模型：全局单会话（修复 A 类 bug 3/4，且比原修法更彻底）

- **导演只有一个、身份恒定 → 会话全局唯一**：prep/live 双会话模型废弃，"按 program_id 互相覆盖"的 bug 连根消失（不需要复合主键了）。`program_sessions` 退化为全局会话的存档（单条滚动）。
- **直播事件流注入同一条会话**：评论/礼物等事件以批次形式进入导演会话（现状机制保留）；收播时的收官总结作为天然分界。直播中想给另一个节目写稿：遵循"一个时间线一个任务"，新任务排队或显式打断。
- **直播中禁止启动另一个节目**：`ProgramPlaybackService.launch` 增加守卫——live 进行中 launch 另一节目直接报错（UI 层对应：开播确认页禁用并提示"先结束当前场次"）。

### 3.3 知识范围消费端补上（修复 A 类 bug 1）

- `search_knowledge` / `check_price` 传入节目 `knowledgeScope` 做过滤：`'*'` 全库、id 数组则限定范围。
- 开播定格时把 knowledgeScope 冻结进会话资产。

### 3.4 音频存储安全（修复 A 类 bug 2/5）

- `TtsStreamService.chunkedFallback`：兜底拿到的缓存 blob **禁止删除**，改为登记 temp 引用让 GC 管。
- temp 级 blob 到期清理前检查引用计数：有 owner 引用的跳过删除并告警（忘记 promote 的路径显式报出来，不是静默丢文件）。

### 3.5 运行态保持（修复 A 类 bug 6）

- 导演模型下"换主播"= `switchPresenter`，**不重启会话**，`programVoiceId` / `programGapMs` 等运行态天然保留（原 handoff 的 stop/start 路径废弃）。
- "重启会话"重置触发器单场预算改为显式行为，UI 提示。

### 3.6 提示词重构（随导演模型大幅简化）

**现状**：`PromptTemplateService.ts` 三个版本人设中心提示词（"你是「name」，一个脑管全场"）+ 版本检测/自动升级机制（`PersonaService.ts:33-41`）；`buildSystemPrompt` 把人格/角色规则/声音边界逐层拼进 system。

**导演模型下收敛为**：导演身份（恒定短段，系统内置，无版本升级机制）+ 卡司资料（数据注入，写谁的词带谁的卡，taboos 升级为内容红线）+ 节目上下文（数据）+ 写稿/回复规范（一份，含演法标记手册，视角从"你说话时用"改为"你写台词时用"）。

**整段删除**：roles 相关规则（`PersonaService.ts:125`"不要用 say 的 role 虚拟对话者"）、声音边界解释（`PersonaService.ts:196`"节目选角对现场说话不生效"）、`set_voice` 的"回到人设卡音色"语义（改为 `switch_presenter` 从卡司里换人，或仅 UI 操作）、handoff 换人格相关逻辑。

### 4.2 AgentPanel（全局驻场面板）

**三种停靠状态，同一个组件，会话连续**：

| 状态 | 形态 | 切换 |
|---|---|---|
| 浮窗 | 非模态、可拖拽、可缩放（最小 360px）、位置尺寸记忆 | 拖到屏幕右缘自动吸附为侧边栏 |
| 侧边栏 | 停靠右缘、挤压页面内容（不遮挡）、宽度拖分割线可调（320px ~ 50% 屏宽） | 标题栏点"弹出为浮窗"回到上次浮窗位置 |
| 最小化球 | 右下角悬浮球，任务后台跑，完成冒绿点 + toast；直播台抬高一个播放条的量，不压底部音量/状态栏 | 点开恢复原状态 |

**关闭 ≠ 停止**：点 × 关窗，任务继续跑，对话记录保留，重开原样恢复。只有显式"停止"才中断任务。

**纯对话区，不挂操作**：面板就是"跟导演说话"（时间线 + 输入框），原「操作」选项卡已撤——其中只有「人工播报」还留在播出层（吸底播放条最右的「⋯」菜单），其余都不要了：切场景由导演按剧本自己推进（`advance_scene` / `goto_scene` 工具在，人工按钮与 `program:goto-scene` IPC 一并删除）、调音量就用播放条上的主音量滑杆、"场控指令"本来就是对话。

**浮窗不许压标题栏**：应用自绘的 40px 标题栏（`DragStrip` + 右侧系统窗口按钮）是保留区——侧边栏态从 y=40 起排；浮窗态拖拽/缩放全程钳制 y ≥ 48，位置尺寸记忆存的是钳制后的值。

**面板结构**：

```
┌─────────────────────────────┐
│ ● 小云（导演）       [⇥][×]  │ ← 固定身份：导演本人（⇥ 在浮窗/侧边栏之间切）
│ 📎 底稿工作台·生命是一个… [×]│ ← 上下文芯片（可摘除）
├─────────────────────────────┤
│  时间线：                    │
│  · 用户气泡（靠右）          │
│  · 导演正文（流式）          │
│  · 思考过程·12s ▸（折叠）    │
│  · 🛠 查了商品资料（浅色行）  │ ← 工具调用翻译成人话
│  · ┌ 请示卡 ────────────┐   │
│    │ 要清空现有 8 段重写吗？ │
│    │   [确认]   [算了]      │
│    └──────────────────┘    │
│  · 任务进度卡：写稿中 6/8 段 │
├─────────────────────────────┤
│ [写开场] [续写] [润色]       │ ← 快捷指令随上下文变
│ ┌─────────────────────┐ [➤] │
│ │ 跟导演说点什么…       │     │
│ └─────────────────────┘     │
│ 📎 附件        /clear 清空   │
└─────────────────────────────┘
```

**富文本渲染 = streamdown（懒加载）**：导演回复里的表格/任务列表/代码高亮/公式走 `components/Markdown.tsx`（包 streamdown，Apache-2.0，React 19 peer）——它专为 AI 流式输出设计，自带 `parseIncompleteMarkdown`（未闭合标记补全）与块级入场动画；表格带「复制表格」（中文文案走 `translations`），下载/全屏关掉；外链交系统浏览器不弹确认。三件事：① **懒加载**（核心 ≈150KB gzip，只在真渲染回复时下载，加载期间用自研 `MiniMarkdown` 兜底）；② Tailwind 要 `@source` 扫它的类名 + 入口 `import 'streamdown/styles.css'`；③ 构建分块 `manualChunks` 把 markdown 单独拆块（不拆会跟 mermaid 合成 ~1MB 异步包）。中间流式文本仍是纯文本、只有 final 才富文本——刻意的性能取舍（每 60ms 重排整段 markdown 不划算）。

**性能改造实测（同一段长回复流式，改造前后对比）**：

| 指标 | 改造前 | 改造后 |
|---|---|---|
| `agent:status` 广播次数/秒 | 18.5 | 6.0（120ms 合并上限 ≈8） |
| 每个文本条目对应的 status 广播数 | 3.6 | **0.43**（↓8.4×） |
| 时间线长任务（>50ms 阻塞帧） | — | **0**（15.9 条/秒流式期间） |

做法：① 主进程 `broadcastStatusThrottled()`（120ms 合并）+ `heavyStatus()`（资产指纹/场景/卡司名/接线缓存 1s，`refreshProgramGate`/`setState`/`stop` 时失效）——把"每个 delta 查 4 次库 + hash 全部提示词模板"变成"每秒一次"；② 渲染层行级 `memo`（`TimelineLine` + ToolCard/ToolGroup/ThinkingBlock/AskCard，`upsert` 只替换变化那条所以引用稳定）+ 请示卡自己走秒（父组件原来每秒 setState 会把整条时间线重渲染）+ 滚动改 rAF 合并并在非贴底时给「↓ 回到底部」。

③ **IPC 发增量**：主进程只发新增片段（`append: true`），定稿那次发全文兜底对账，渲染层累加。实测"按同一规则累加 === 定稿全文"（207 === 207，无丢字/重复）；顺带把"每 60ms 一次整段 UPSERT 落库"改成**只在定稿落库**，长回复的写放大一并去掉。
④ **虚拟列表**：`react-virtuoso`（19KB gzip / 0 依赖）替掉手写滚动容器——空态与"正在生成"占位走 `EmptyPlaceholder`/`Footer` 槽，142 条历史只渲染 7 条、DOM 87 个节点。
**贴底跟随不能交给 `followOutput`**（踩过的坑）：流式期间它无法区分"内容刚变高"与"用户翻上去了"，定稿那次正文从纯文本换成富文本、高度一变就被判成"用户离开底部"，从此不再跟随（实测掉到离底 329px）。现在自己维护"贴底模式"：只有真实用户动作（滚轮向上/拖到上方）才退出，内容一变就 `scrollToIndex({ index: 'LAST', align: 'end' })` 钉住（实测 22/22 采样贴底）。
⑥ **streamdown 的三个实情**（都实测过）：① 它**不自带主题**——`styles.css` 只有 1KB 进场关键帧，视觉全在它组件的 Tailwind 类名里（所以 `@source` 必须加），可配置的只有 `components`（覆盖任意标签渲染）、`shikiTheme`（仅代码高亮配色）、`remarkPlugins/rehypePlugins`（解析管线）、`animated`、`translations`、`controls`——字体/字号/颜色都在我们这边；② **单换行会被并成空格**（CommonMark 软换行），导演的"一行一条"汇报并成一大段就读不出结构，用 `remark-breaks` 把单换行当硬换行（空行照旧分段）；③ **传 `remarkPlugins` 会顶掉它的默认项**（`defaultRemarkPlugins`: gfm/codeMeta），表格立刻解析不出来——必须 `[...Object.values(defaultRemarkPlugins), 自己的插件]`。

⑦ **虚拟化后每行必须包一层 flex 容器**：导演消息靠 `self-end` 右对齐，而块级父容器里 `self-end` 是无效的——那会让自己的消息只在"86% 宽的盒子内"右对齐（实测右边缘 1031 vs 内容右边缘 1409），长消息就从左边一路铺过来，看着像没右对齐。改成 `<div className="flex flex-col px-4 pb-3">` 后，实测三条自己消息右边缘都等于内容右边缘（flush）。

⑧ **思考时长必须由主进程给（踩过的坑）**：渲染端原来拿条目 `ts` 当开始时间跑实时秒表，而增量推送后**库里的 `ts` 是"落库时刻"（＝结束时刻）**，于是恢复出来的旧条目会算成天文数字（实测「思考过程 · 1018s」）。四条一起改，缺一条都不稳：① 主进程 `appendThinking` 记 `startedAt`，定稿那次带 `durationMs`（＝权威时长）并随 ChatEntry JSON 落库；② 渲染端 `durationMs` 优先，本地兜底只在"本会话里看着它写完"时才算（`ts` 是本会话首见时刻，可信）；③ 存档恢复出来的条目记进 `restoredRef`，不给数字、只显示「思考过程」；④ **没封口的思考必须封口**：`stop()` 与 `beginTurn()` 里清 `thinkings` 之前先 `finalizeThinking()`——旧代码里把会话停了却不封口，条目永远 `done=false`，秒表就一直往上跑（这就是 1018s 的来路）。渲染端再加一条兜底：只有时间线**最后一行**才可能在"正在思考"（被别的条目顶下去说明早结束了）。实测：新条目主进程 `durationMs=2014ms` ↔ 界面「思考过程 · 2s」；重启后从库里恢复仍显示「思考过程 · 2s」；`agent.stop()` 打断在思考中的条目 → 定稿 `durMs=582` 且标签恒定不再滚动；`stopGeneration()` 打断 → `durMs=59`。

⑤ **富文本排版**：装 `@tailwindcss/typography`，`Markdown` 外面套 `prose prose-sm`，并把 `--tw-prose-*` 接到本应用 token 上（一套变量适配明暗）；`prose-headings/-p/-ul/-li/-code/-pre/-table` 逐项调过间距与字号，正文保持 13px/行高 24px 与其它正文一致。

⑨ **「只在挂载时拉一次」的清单会过期（页面是常驻不卸载的）**：App 用显隐切页，组件不会重新挂载，所以 `useEffect(..., [])` 拉来的清单在别处改动后一直是旧的——实测节目页改名/删节目后回直播台仍显示旧名；知识库更明显：API 刚建的文档，页面仍显示「资料文件 · 0」。修法统一成"回到这一页就重拉"（订阅 `page`，`page === 'live' / 'knowledge'` 时 reload）；`switchProgram` 先重拉再按 id 校验存在性，切到已删除的节目要报错而不是弹"已切换"。

⑩ **三处"看着对、其实没生效"的代码（都是实测抓出来的）**：
- **列表的滚动容器长错了层**：评论流/事件流的 `listRef` 挂在 TabsContent 里那个**不溢出**的 div 上，`el.scrollTop = el.scrollHeight` 是空操作——看起来"自动跟到最新"，其实一直不跟。修法：列表自己带 `min-h-0 flex-1 overflow-y-auto`，父级 TabsContent 只负责"撑满 + 激活时 flex 列"（与 `ContentList` 同一套约定）。口径同时统一为**新的在底 + 自动跟随**（主进程的事件快照是"新的在前"，渲染层倒过来）。
- **回调式 key 撞了**：`key={x ?? 'new'}` 这种"来源变了就重挂载"的写法，同一个父节点下并列两处都落到 `'new'` → React 报 `same key`（实测一次加载 7~8 条）。修法：哨兵值各自唯一（`new-entry` / `new-script` / `new-persona` / `new-program` / `new-llm-connection` / `new-tts-connection`）。
- **受控 Select 写 `value={x || undefined}`**：空值那一刻组件是**非受控**，用户选完变受控 → Radix 报 `Select is changing from uncontrolled to controlled`（实测设置弹窗打开时命中）。修法：值永远是字符串，空值用显式哨兵项（`<SelectItem value="__none__">（未选）</SelectItem>`），`DirectorPane` 的模型选择就是这么改的（同类写法在节目「声音安排」里也有过一处，那块后来整体删掉了）。

⑪ **状态栏两格各讲一件事**：左边只讲**本机播出**（`播报中` / `已暂停` / `就绪`，暂停以主进程 `speakingPaused` 为准，不做本地镜像），右边只讲**输出通道**（`推流中 Nkbps` / `伴侣出声` / `推流未配置` / `未推流` / `未出声`）。改前两格都在讲"开播"，暂停时左边还写「播报中」。同理，非预制模式没有"章"可退，`上一段` 按钮直接不显示（原来永远灰着，像坏了）。

⑫ **react-doctor 扫描结论与有意保留的项**：58 个渲染层问题按"会不会出真错"分两批——真错的那批（渲染期写 ref、setState updater 里套 setState、撞 key、非受控↔受控、prop 抄进 state、下标 key）全修；**性能类微优化（`js-set-map-lookups`/`js-combine-iterations`/`async-await-in-loop`，八成在主进程服务里）暂不动**，那些是"为改而改"。确实**不该改**的也留了：`MiniMarkdown` 里列表与块的 `key={index}`（每次从文本现解析出的无状态元素，不持有输入/焦点/动画，重排只是原地换文字，已加注释说明）、`WaveMeter` 的七根电平条（写死常量数组）、`Markdown.tsx` 里 streamdown 的包装组件必须写在 `lazy()` 工厂里（要拿到 `mod.defaultRemarkPlugins`，提到模块作用域就得静态 import，会丢掉懒加载）。另外 react-doctor 的**死代码检查在本仓库跑不完**（worker 120s 硬超时，`Dead-code worker timed out after 120s`），所以"未使用的文件/导出/依赖、循环依赖"这片没扫到。

**性能改造计划（按投入产出比）**：① 主进程 `status()` 广播瘦身（现在每个 text_delta 都算 `assetsStale`（含全部提示词模板 hash）+ 4 次同步 SQLite 查询 + 携带整段 draft，且未节流——这是"卡"的第一来源）→ ② 时间线行级 `React.memo` + 滚动改 rAF + 非贴底不抢滚动 → ③ IPC 改发增量而非全文快照 → ④ 条目多时上虚拟列表（`react-virtuoso` 19KB gzip/0 依赖，自带 followOutput 粘底；或更轻的 `virtua`；⚠️ `@virtuoso.dev/message-list` 是商业授权，别引）。

**时间线只属于导演**：条目不再盖"当前出镜主播"的戳（那是旧模型：主播带大脑）；谁在出镜看播放条与状态栏。发出指令后，在导演第一条动静（思考/文本/工具）到达前显示「正在生成回复中…」占位，别让人以为卡死。

**关键行为**：

1. **上下文注入**：从哪里唤起，任务目标就是哪。底稿工作台唤起 → edit_draft 默认目标是该节目；播控台唤起 → 现场调度模式；其他页面 → 通用助手。芯片可 × 掉退回纯聊天。
2. **导演身份恒定，无模式硬切换**：面板里永远是导演本人，工具集随上下文给（写稿工具 / 现场指挥工具 / 通用工具）。不再有"编剧模式/直播模式"的切换。
3. **生成即所见**：导演调 edit_draft 时底稿工作台实时新增段落，用户当场可手改；导演再改基于最新内容，不覆盖人的修改。
4. **一个时间线一个任务**：大任务不并行，新任务排队或显式打断。
5. **请示卡**：破坏性操作（清空、重写、改正在播的段）必须确认。
6. **工具行人话化**：默认显示"查了商品资料""改了第 3 段"，原始工具名/参数/耗时收进"展开技术细节"。
7. **宽度自适应**：窄态只有时间线 + 输入框；宽态（>600px）展示完整工具细节和思考过程。
7b. **写稿/开播前自动应用资产变更**：system prompt 是会话出生时组装一次（导演手册 + 卡司资料 + 节目上下文），改了节目/卡司/剧本就得重开会话才生效。写稿（`startDrafting`）与开播（`launch`）不再依赖用户去点黄条的「立即应用」——这两处检测到 `assetsStale` 就先重开会话（历史落库后带着重组装，开播路径在置开播态之前重开，不会触发下播复盘），导演上场时手上的卡司就是最新那套。
7c. **写稿任务书自带卡司名单**：`user.draft_brief` 渲染完再附一段「本场卡司」——节目定了卡司就点名（只用这几位，写谁的词钻进谁的人设，不许凭空造人），没定就报可用名单让导演自己挑（单人节目选一位主讲，双人对谈按人设分派 role）。合成嗓音仍由底稿的 voiceId / 合成弹窗决定，与卡司无关（4.4）。
8. **面板里不再切主播**：导演身份固定，AgentPanel 没有主播切换器。**出镜主播是播出属性**，选择入口在开播确认页和直播台顶栏（见 4.5/4.6）——切的是"谁的风格卡 + 嗓子"，轻操作（`switchPresenter`），不换脑、不重启会话，直播不断。导演建主播卡 = 选角，不影响任何进行中的播出（原"agent 建卡静默换主播"问题随模型消失）。

### 4.4a 统一音色选择器（UnifiedVoicePicker，全局共享组件）

**问题**：现状是"级联选择 + 裸 voiceId 手输框"并存（`AnchorsPage.tsx:313`、人工播报弹窗 `LivePage.tsx:1724`），手动输入的裸 ID 丢失平台上下文——路由时不知道往哪家服务商送，填错就是无声失败。

**组件形态**：三段式，任何需要选音色的地方统一用它（替换 VoiceCascadePicker 和所有裸输入框）：

```
┌ 音色 ─────────────────────────────────────┐
│ 服务商：[火山引擎 ▾]  模型：[cosyvoice-v2 ▾] │
│ 音色：  [选择已登记音色 ▾]                   │

│     [粘贴服务商控制台里的原始 ID，如         │
│      火山的 speaker ID / 百炼的 voice id]   │
└──────────────────────────────────────────────┘
```

- **值永远是完整路由三元组** `{ ttsConnectionId, ttsModelId, voiceId }`——手动输入的 ID 也挂在选好的服务商+模型下，服务商控制台复制的原始 ID 直接粘贴即可用，不会再出现"孤儿 voiceId"。

- **替换点全清单**（现已全部落地）：人设卡嗓音（`AnchorsPage.tsx`）、卡司配音（节目编辑）、人工播报弹窗（`LivePage.tsx`）、合成弹窗（4.4）、角色音色输入（`AnchorsPage.tsx` roles，roles 废弃前顺带替换）。节目编辑里的「声音安排」一度也换成了它，随后**整块删掉**了：合成那一步本来就一定要人选声音，节目上再存一份只会互相打架（见 §「声音不在节目里配」）。
- **`ProgramAudioConfig` 的现状**：界面上已无入口，字段保留给老数据与导演工具（`save_program` 仍可写 `connection/model/voiceId/cast`）。主进程 `resolveFrozenSnapshot` 的优先级是 **段落单独指定 > 角色表第一条 > 节目默认音色**；因为 UI 不再能写自定义配置，实践中走的是「合成弹窗 override」这条路（`ProduceVoiceOverride`：单音色 / 播客双主持 + 开场结尾音乐 / 强制跟随主播）。两个细节：① 没配默认音色时算出来的指纹与旧版一致（升级本身不会把已有产物标脏）；② 音色库删音色时的「谁在用」把节目默认音色也算进去（`VoiceService.usage`）。
- 旧的"接入::模型::音色"复合串手输语法（`AnchorsPage.tsx:313` 占位符那套）废弃——破坏性更新，**存量裸 voiceId 直接废弃不做迁移**：凡是没有完整路由三元组的音色一律视为"需重选音色"，预检会拦下并指路。

### 4.6 播控台统一骨架

```
┌──────────────────────────────────────────────────┐
│ UpNext（同一壳，占主体，内容按模式填充）           │
│ [接下来] [评论流] [事件流]                         │
│  · prepared → 章节列表（状态/时长/点播）           │
│  · rolling  → 话术池队列（话轮分组，保留现状）     │
│  · improvised → 实况流 + 最近说过                 │
│  · …（列表滚动区）                                │
├──────────────────────────────────────────────────┤
│ NowPlayingBar（三模式同一套，吸底，音乐播放器式；页面无顶栏）        │
│ ━━━━━━━━●────────────────（贴边进度线：只有确定时长才出现）        │
│ 测试·保温杯专场 ▾          ⏮  ⏸暂停  ⏭  ☰ │ ⏹ 结束本场   🔇 🔊━━ ⋯ │
│ 小陶 · 本人2 · 02:13 / 05:40（有确定时长才带时间）                  │
```

- **NowPlayingBar 吸底，音乐播放器式单行（高约 70px，`py-4`，别挤）**：左＝**节目名（可换）+ 当前出镜主播·嗓音**（播放器的曲名/歌手位；**不铺稿子文字**——正在播什么归内容区，那边有行内标记：滚动/即兴是播放行高亮 + 状态图标，预制是章节行的「播报中」徽章），中＝统一控制（上一段 / 暂停继续 / 下一段 / 队列 / 结束本场），右＝音量（图标即静音开关）/ 「⋯」。三模式同一套，只有中键语义按模式变：prepared 是章级跳播（禁用条件也不同），rolling/improvised 的下一段＝跳过当前这条。
- **进度线贴条顶，整条宽度**：只有"有确定时长"的内容（预制章节音频）才显示，可拖动 seek（松手才真跳）；播客/即兴/滚动没有确定时长，整条不出现——不是显示 0%，是根本不画（网易云播客的做法）。
- **UpNext 占主体**：同一卡片列表壳，只换列表内容；评论流/事件流收成 tab，开 `allowLiveEvents` 的节目三模式可见。
- **正文排版统一**：三种模式（滚动/即兴/预制）与场记的正文都走同一个组件 `ContentText`（`text-[13px] leading-6`；`muted` 只压字色不改字号行高）——换播放模式字体不再变样。演法标记照旧渲染成行内 chip。
- **稿子完整可见**：每段/每章默认显示全文（预制文章整篇可见，长文可折叠但**绝不截断成一行省略号**）；段、文章、即兴话术三种形态统一支持。
- **演法标记行内渲染**（所有稿子展示处统一：UpNext、底稿工作台、场记详情）：`<pause>500</pause>` → `⏸ 500ms` 小标签；`<cot text=情绪>句子</cot>` → 情绪名小标签 + 句子正常显示；`<fx>音效</fx>` → `🎵 音效` 小标签。编辑态才显示原始语法，展示态永远不出现裸标签。
- **「⋯」动作菜单在吸底播放条最右（紧挨音量）**，两项：人工播报 / 自动响应（白名单 + 互动总闸，播出中可改）。音量就近用旁边的滑杆，不再单开「调音量」弹窗；切场景不做人工入口（场景推进是导演的事）。顶栏只留节目选择与启动/结束。
- **页面没有顶栏**：节目选择搬进播放条左槽（副标题里的 `节目名 ▾`，直播中只读），启动/暂停/结束搬进中槽，推流与状态在底部状态栏——顶部整行让给 [接下来/评论流/事件流]，视觉上少一层。
- **三个动作各给一种语言，不再"一排圆钮"**：`▶ 启动节目`（primary 实心带字，仅未开播出现）／`⏸ 暂停`（中性描边带字，仅直播中出现）／`⏹ 结束本场`（红字描边带字 + 二次确认，仅直播中出现）。启动与"暂停+结束"永不同屏；同屏的暂停与结束靠颜色、文案与二次确认区分——**收场是不可逆的重操作**，误触代价高。
- **音量图标即静音开关**：点一下音量收到 0（AI 两路一起哑：本机监听 + 推流，麦克风人声不受影响），再点回原音量；精细调节用旁边的滑杆。原来那个单独的「急停声音」按钮已删除——它的语义（只掐声音不结束本场）与这个开关重合，少一个按钮少一次犹豫。
- **顶栏只显示"谁在出镜"，不提供切换**（人设卡没有大脑，单独摆一个切换器语义不清、还和出镜徽章重复）。换人设的入口是：节目卡司多选（节目编辑）+ 主播团激活卡；直播中要换人由**导演自己**调 `switch_presenter` 工具（换风格卡 + 换 voiceId + 未播存货重合成，不重启会话、直播不断）。AgentPanel 里也没有主播切换器，两边一致。
- PreparedPanel / ImprovisedPanel 改造为 UpNext 的填充组件，NowPlayingBar 共享。

|---|---|

## 9. 可选扩展：对外 MCP 接口（开发者向）

**定位**：让外部 agent（Codex / Kimi Code / Claude Code）能直接操作系统——在 IDE 里说"给保温杯节目再写 5 段催单话术"直接入库、脚本化批量写稿、读场次数据做外部分析。**不是小白路径，默认关闭。**

> 注意区分："用 GPT 系模型写文案"不需要 MCP——LLM 接入配一个 OpenAI 协议服务商、人设卡选它当大脑即可。MCP 开放的是"系统能力"，不是"模型能力"。

**实现**：主进程起一个 MCP server（Streamable HTTP，本地端口 + Bearer Token，设置页生成/轮换 token，默认关闭）。SDK 已有（`@modelcontextprotocol/sdk`，评论连接器同款）。

**暴露工具白名单（克制原则：读多写少，不暴露播放控制）**：

| 类别 | 工具 | 说明 |
|---|---|---|
| 读 | `list_programs` / `get_draft` / `list_sessions` / `get_session_detail` / `search_knowledge` | 查询类全开放 |
| 写（内容） | `create_draft` / `edit_draft` / `create_program` | 只限内容生产，等同底稿工作台手动操作 |
| 禁止 | 开播/停播/删除节目/清空底稿/改配置/推流 | 一律不暴露 |

**安全**：仅监听 127.0.0.1；token 鉴权；写操作全部走与 UI 相同的 service 层（不走捷径）；调用记日志（设置页可见最近调用）。
