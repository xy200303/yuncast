# 核心概念

## 节目是模板，场次是留档

「节目」是一份配置模板：一场带货直播、一本有声书、一期播客，都先建成一个节目，把形态、播出方式和播完策略配好，然后反复拿它开播。每真正播出去一次，就在「场次记录」里留下一条**场次**——这场谁播的、用的什么模型、逐条说了什么、观众说了什么，只属于这一场。改节目不会动到已经播过的场次。

全局只有一个导演会话和一个话术池，所以同一时间只跑一场。直播中不能换节目，节目里的结构性改动也在下次开播生效；开播那一刻的状态会定格成一份快照，整场按快照走。

节目由三个维度定义：

### 内容形态

| 形态 | 界面说明 | 适合场景 |
| ---- | -------- | -------- |
| **一个人讲** | 一个主播从头讲到尾 | 单主播带货、商品宣讲、FM 独白 |
| **多人聊天** | 几个人你一言我一语地聊，像播客对谈 | 双人播客、访谈式直播 |
| **照着稿子读** | 照着现成的稿子念 | 有声书、文章朗读、新闻播报 |
| **分角色表演** | 主播分饰多角演剧本，每个角色可以有自己的声音 | 广播剧、剧情带货 |

形态会影响合成与导出的计数单位：一个人讲按「段」、多人聊天按「个环节」、照着稿子读按「章」、分角色表演按「场」。

### 播出方式

| 播出方式 | 合成策略 | 界面说明 |
| -------- | -------- | -------- |
| **现场发挥** | 说一句合成一句 | 主播看着直播间动态临场说，无需底稿 |
| **边播边准备** | 一段一段滚动合成 | 一边播前面的、一边合成后面的，可随时改稿插播 |
| **全部做好再播** | 开播前整本合成完 | 先把音频全部做好，再播放或导出，适合有声书、播客 |

### 播完之后

只对「边播边准备」和「全部做好再播」有意义，现场发挥没有这一项。

- **播完停止**：一轮播完通知主播说收尾词，说完节目结束
- **循环播放**：播完一轮从头再来，适合无人值守的轮播场

结束方式在「场次记录」里分开记：点「结束本场」是**手动收播**，跑完「播完停止」是**播完收播**，另有紧急停止、应用退出、异常中断几种标记。

## 声音在合成那一刻定

节目里没有「声音安排」这一栏。所有合成入口——节目卡的「底稿库」、预制节目的「继续合成」、直播台预检里的「提前合成全部」——都会先弹「合成声音」窗口，在那里选这次用哪把嗓子：

- **当前主播嗓音**：跟着出镜主播走
- **节目声音安排**：只有老节目存过自定义声音配置时才出现（新建节目已没有这一栏）
- **选择其他音色…**：接入 → 模型 → 音色，也可以直接填音色 ID；选到播客模型还要挑主持人 A、主持人 B 和开场 / 结尾音乐

窗口会先说清这次要合成多少：「本次合成 N 段 · 约 X 分钟」，已就绪且文稿没改过的单元自动跳过。确认之后才开始合成，选定的这把嗓子**冻结进每一段产物**——之后换主播、改人设、改节目配置都改写不了它；想换声音就重新合成。已有段落是别的嗓音时会提醒会混音，并给「全部重合成，统一为本次选的声音（旧音频清掉）」。

预制节目还支持给单个单元「导入外部音频」，挂上去的音频跳过语音合成，也不受这套冻结规则影响。

## 主播与节目解耦

主播（人设卡）和节目是分开的：同一个主播可以串不同的节目，同一个节目也可以换主播。主播只管人设与表达风格；声音不挂在节目上，每次合成时单独选，所以换主播不必动节目，改节目也不会悄悄换掉已有音频。

改人设、改模型、改剧本之后，正在跑的会话用的仍是启动时的版本，界面顶部的黄条会提示，需要当场生效就点「立即应用」——代价是当前对话上下文清空。

## 事件触发器

欢迎新人、送礼感谢、点赞里程碑、冷场自救这类「条件动作」是节目级开关：在节目的事件规则里勾选启用哪些，同时也能决定要不要把直播间动态喂给主播。规则按事件来源分三组：直播间事件、节目状态、业务事件。

内建触发器有六个，都可以关：

| 触发器 | 触发事件 | 默认 |
| ------ | -------- | ---- |
| 欢迎新人 | `viewer.join` | 开 |
| 送礼感谢 | `gift.received` | 开 |
| 点赞里程碑 | `like.burst` | 开 |
| 冷场自救 | `pool.empty` | 开 |
| 价格变动提醒 | `product.price_changed` | 开 |
| 整点带节奏 | `timer.interval` | **关**（定时叫醒会持续消耗 tokens） |

把「让主播看到直播间动态」的总闸关掉，评论 / 礼物 / 进场 / 点赞整类事件都不再派给主播，主播只演自己的内容。水位类触发器（冷场自救）只在「现场发挥」和「边播边准备」里放行——「全部做好再播」的音频已经做完，空池不需要自救。「自动响应」面板在直播时也能改，改完立刻生效。

## 话术池：一切声音的唯一出口

主播临场说的、底稿预合成的、你人工播报的，全部进同一个话术池，按四档排出先后：**打断 > 下一条 > 常规 > 垫底**。回评论、救急的话走「打断」立刻插进来，其余排在当前这条之后按序接着播，垫底的只在前面都空了才轮到。所以任何来源的声音都不会叠在一起乱播。

队列按话轮分组：同一档、同一次说话里的几条是原子播出的，不会被拆开插队。每条话术在「接下来」里有自己的状态——待合成、合成中、就绪、播报中、已播、被打断、已撤销、失败、已过期；五分钟内合成失败的会在队列底部单独列出来。

## 评论与事件流

评论、进场、礼物先进事件流，再决定要不要叫醒主播。处理顺序是：按连接器事件 ID 去重（最近 3000 条）→ 过滤纯表情、单字刷屏、同人同内容（30 秒内只累计次数）→ 相同内容归组计数 → 识别高优先级 → 聚合 → 限速。

聚合窗口是自适应的，5 到 30 秒：按最近 30 秒的事件到达速率换算，大约每秒 3 条时顶到上限。每分钟最多唤醒主播 6 次，单批最多带 20 条、合计 1500 字，超了折成摘要；没处理的事件 5 分钟后过期，不会在很久以后突然补答。含问句、价格、售后这类词的评论标为高优先级，主播空闲时 2 秒就唤醒。

主播像真人一样看到才回、没看到不回；回一个还是回一批由它自己判断。直播台左栏的「事件流」选项卡可以实时看到喂给主播的每一批事件。

## 冻结快照与预制门禁

开播那一刻会把这一场的导演、出镜主播、声音和策略定格成快照，整场按这份快照走，不会播到一半被后台的改动带偏。

「全部做好再播」的节目开播前还要过一道预制门禁：逐段核对音频是否齐、是否还跟当前文稿对得上，缺项照实列出来、不静默跳过，并给你两条路——「继续生成（补齐音频）」把缺的和失败的一起补上，跑完自动重新过门禁；或者先「仅播放已完成部分」。同一套门禁在导出时也会走一遍。
